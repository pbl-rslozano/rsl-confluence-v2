# Only Coins.ph Opens the Peso Door

*Philippine exchange API integration for the rsL Crypto Confluence Terminal: feasibility, endpoints, constraints and design. v1.0 2026, research date 7 November 2026.*

Yes, it is feasible, but only for one exchange. **Coins.ph is the only Philippine centralized exchange with a documented, unauthenticated market-data API.** It sits at `https://api.pro.coins.ph`, and its klines, 24-hour tickers, depth and exchange-info endpoints are close to a copy of Binance spot v3, so the terminal's existing Binance kline parser can be reused almost unchanged. PDAX, the other licensed Philippine exchange, offers only partner APIs that need a business sign-up and credentials. GCash GCrypto, Maya and GoTyme have no developer price feed at all. That rules all four out under the app's credential-free rule. Three constraints matter more than the endpoints. First, Coins.ph cut its limit to **120 requests per minute per IP on 16 March 2026**, a tenth of what CCXT and older code assume. Second, **about 89% of its volume is USDT/PHP and USDC/PHP**, so its peso crypto pairs are thin and make a weak primary source for technical analysis. Third, the official docs say nothing about CORS. **No live response or CORS header was observed in this session**: the research sandbox blocked api.pro.coins.ph, docs.coins.ph and doc.restapi.pdax.ph, and no browser was reachable. One browser-console test therefore decides the transport design before any code is written. The design that fits the app's rules has five parts: a new `coinsph` source with a quote-currency abstraction, a scheduler paced to the 120/min budget, a platform-specific transport layer kept inside `packages/adapters`, an ADR-0003 amendment that limits access to public `/openapi/quote/*` paths, and per-source confluence scoring that treats Coins.ph as a "Philippine premium" overlay rather than a replacement for USDT venues.

## Two licensed exchanges, one usable API

The Philippine licensed market is small and effectively frozen. The BSP's VASP list as of 15 October 2025 contains **10 active VASPs**. Only two of them, **Coins.ph (Betur Inc.) and PDAX**, run public exchanges with market data ([Fintech News PH](https://fintechnews.ph/61554/crypto/here-are-the-licensed-cryptocurrency-exchanges-in-the-philippines/)). The BSP moratorium on new VASP licences, which began in September 2022, was extended **indefinitely from 1 September 2025** ([Fintech News PH](https://fintechnews.ph/68110/crypto/bsp-extends-moratorium-on-new-vasp-licenses-indefinitely/)). No source found reports that it has been lifted, so no new licensed venue is likely to appear soon. CoinGecko's Philippines country page lists only Gate, BingX and Coins.ph; PDAX is not there ([CoinGecko](https://www.coingecko.com/it/cambi/country/philippines)). CCXT supports Coins.ph as `coinsph` and has no PDAX module ([CCXT docs](https://docs.ccxt.com/docs/exchange-markets)).

PDAX does publish API documentation hosts, but everything readable about them points to partner access only. PDAX Connect offers "enterprise-grade APIs" behind a corporate sign-up form, and its partners operate under PDAX's VASP licence ([PDAX Connect](https://pdax.ph/caas/)). The CaaS docs host is titled "Authentication" ([PDAX CaaS docs](https://doc.caas.pdax.ph/)). OTC is limited to Prime clients, with quotes delivered through a group chat ([PDAX OTC](https://pdax.ph/treasury-otc-features/)). Since its 2023 system switch, PDAX retail trading has used market orders only, and the old order-book site was retired ([PDAX FAQ](https://pdax.ph/learn/pdax-system-switch-faqs/)). That fits a brokerage model more than a public order book. The main reference host, `doc.restapi.pdax.ph`, could not be read: robots.txt blocked it and the proxy returned 403 ([PDAX API Reference](https://doc.restapi.pdax.ph/)). So "PDAX has no public endpoint" is a strong inference, not a verified fact. The next step is to open that page in a normal browser.

The e-wallets add nothing new. GCrypto is powered by PDAX, and GCash states that its chart data "is available for viewing in the GCash app only" ([GCash Help](https://help.gcash.com/hc/en-us/articles/61501229130521-What-is-the-GCrypto-token-page)). Maya's prices are "dictated by the third party provider", which is Coinbase, plus a margin ([Maya terms](https://www.maya.ph/crypto-terms-and-conditions)). GoTyme's 11-coin, USD-denominated crypto product runs on Alpaca's B2B Broker API ([Alpaca](https://alpaca.markets/blog/gotyme-bank-launches-crypto-trading-in-the-philippines-in-partnership-with-alpaca/)).

| Venue | Keyless public market data | Verdict for the terminal |
|---|---|---|
| Coins.ph (Coins Pro) | Yes: REST plus WebSocket, Binance-style | Integrate |
| PDAX | No documented public endpoint; partner APIs only | Exclude; recheck `doc.restapi.pdax.ph` manually |
| GCash GCrypto | No (in-app only; prices come from PDAX) | Exclude |
| Maya Crypto | No (Coinbase plus margin) | Exclude |
| GoTyme Go Crypto | No (Alpaca Broker API, USD) | Exclude |

Regulation does not block a reader in Saudi Arabia. SEC Memorandum Circulars 4 and 5 of 2025, effective 5 July 2025, cover entities that offer crypto services "to persons in the Philippines" ([BitPinas](https://bitpinas.com/regulation/sec-clarifies/); [Baker McKenzie](https://insightplus.bakermckenzie.com/bm/capital-markets/philippines-sec-issues-rules-and-guidelines-on-crypto-asset-service-providers-casp)). No source found addresses consuming public price data. The binding limits are therefore the exchange's own terms and rate limits. Coins.ph's user agreement was updated effective 16 April 2026, and the announcement does not mention API use or redistribution ([Coins.ph Help Center](https://support.coins.ph/hc/en-us/articles/54476354076185-Coins-ph-User-Agreement-Updates-Effective-April-16-2026)). The full agreement was not reviewed, so redistribution terms remain unknown.

## A Binance clone with one tenth of the headroom

The REST base is `https://api.pro.coins.ph` and the WebSocket base is `wss://wsapi.pro.coins.ph`. All endpoints return JSON in ascending order with millisecond timestamps ([Coins.ph REST docs](https://docs.coins.ph/rest-api/); [WS docs](https://docs.coins.ph/web-socket-streams/)). The docs define security type `NONE` as endpoints that "can be accessed freely". None of the market-data endpoints carries a security type, so all of them are keyless. The repository behind the docs was last committed on 9 September 2026 and has a changelog running to that date, even though the page header still reads 2022 ([coins-docs repo](https://github.com/coins-docs/coins-docs.github.io)).

| Purpose | Path | Key params | Weight |
|---|---|---|---|
| Klines | `/openapi/quote/v1/klines` | `symbol`, `interval`, `startTime`, `endTime`, `limit` (default 500, max 1000) | 1 |
| 24h ticker | `/openapi/quote/v1/ticker/24hr` | `symbol` or `symbols` | 1 for one symbol or 1–20 symbols; 20 for 21–100; 40 for 101+ or all |
| Price / book ticker | `/openapi/quote/v1/ticker/price`, `/ticker/bookTicker` | `symbol` or `symbols` | 1 or 2 |
| Order book | `/openapi/quote/v1/depth` | `symbol`, `limit` (max 200) | 1 or 5 |
| Symbols | `/openapi/v1/exchangeInfo`, `/openapi/v1/pairs` | optional `symbols` | 1 (CCXT uses 10) |
| Health | `/openapi/v1/ping`, `/openapi/v1/time` | none | 1 |

Source: [Coins.ph REST docs](https://docs.coins.ph/rest-api/); [CCXT coinsph.js](https://github.com/ccxt/ccxt/blob/master/js/src/coinsph.js).

The kline array is **Binance's first 11 fields without the trailing "ignore" field**. It supports the same intervals from 1m to 1M, without Binance's 1s, and symbols are concatenated in Binance style, such as `BTCPHP` and `BTCUSDT` ([Coins.ph REST docs](https://docs.coins.ph/rest-api/)). A parser that reads only indices 0–10 works as is. One quirk matters for history backfill: CCXT always sends `endTime` together with `startTime`, noting that `since` works "only when it is 'younger' than last 'limit' candle" ([CCXT coinsph.js](https://github.com/ccxt/ccxt/blob/master/js/src/coinsph.js)). The terminal should page the same way.

The rate limit is the binding engineering constraint. The changelog entry for **16 March 2026** reads: "Change the IP rate limit from 1200 requests to 120 requests per minute". The limit applies across all of `/openapi/*` and is counted **per IP, not per API key** ([Coins.ph REST docs](https://docs.coins.ph/rest-api/)). A 429 means back off, and backing off is "mandatory". Continuing after a 429 brings a 418 auto-ban that grows for repeat offenders "from 2 minutes to 3 days", with a `Retry-After` header. A 403 is a separate WAF block. CCXT 4.5.92 still throttles at `rateLimit: 50 // 1200 per minute` ([CCXT coinsph.js](https://github.com/ccxt/ccxt/blob/master/js/src/coinsph.js)), so any code copied from it will over-request tenfold. Three details are still unconfirmed. The docs do not say whether the 120 counts raw requests or summed weight. They contradict themselves on the trades limit ("last 60" versus a maximum of 1000). And it is unclear whether `check-sys-status` ("Weight(UID): 2") works without a key. The official JS SDK also defaults to `api.coins.ph` rather than `api.pro.coins.ph` ([coins-js-api](https://github.com/coins-docs/coins-js-api)), so the hostname should be pinned to the one the REST docs name.

## Peso books are a remittance rail, not a TA venue

Coins.ph is growing. Spot volume reached **US$500M in November 2025**, up 327% year on year, and hit a daily record of about US$50M in February 2026 ([Philstar](https://philstar.com/business/2026/02/18/2508654/coinsph-trading-volume-soars-500-million)). The volume, however, sits in stablecoin-to-peso conversion. Two CoinGecko snapshots taken on 7 November 2026 put 24-hour volume at **US$24.2M and US$47.6M**. In both, USDT/PHP and USDC/PHP make up about 89% of the total, and **BTC/PHP trades only US$0.3M–1.0M a day** ([CoinGecko: Coins Pro](https://www.coingecko.com/en/exchanges/coinspro); [CoinGecko: Coins.ph](https://www.coingecko.com/en/exchanges/coins-ph)). The venue lists 43 coins and 70 pairs, quoted in PHP, USDT and USDC. Its USDT-quoted books are tiny, with BTC/USDT around US$144K a day.

This changes what the integration is for. Twenty indicators running on PHP alt pairs that trade a few hundred thousand dollars a day will produce gap-ridden, low-trade candles and noisy confluence scores. As a source of trade signals, Coins.ph adds little breadth that Binance, Bybit and Bitget do not already cover. Its real value is information those venues cannot provide: **the local peso price and the USDT/PHP rate**, which together show Philippine demand and the remittance premium. All of this can be computed from hosts the app already trusts or is about to add. The Philippine premium on BTC equals Coins.ph BTC/PHP divided by (Binance BTC/USDT × Coins.ph USDT/PHP), minus one. That gives a local-sentiment overlay with no new FX dependency. The design choice follows directly: Coins.ph gets its own score, and its series are never merged into or substituted for USDT series.

The PHP quote also touches the code. `market-client.ts` hard-codes USDT through `t.symbol.endsWith("USDT")` and strips `(USDT|USD)$` from asset names. Its turnover floor `MIN_QUOTE_VOLUME_NONCRYPTO` is denominated in USD (repository read at commit a90bfc9, v2.5.1). A USD floor sized for global venues would remove almost every Coins.ph pair. The source therefore needs its own quote set (PHP, USDT), its own floor, and a PHP→USD conversion. The cleanest conversion uses the same venue's USDT/PHP last price, so no external FX host is needed.

## CORS is the one unknown that decides the transport

**No live response or CORS header was observed in this session.** The sandbox egress proxy refused api.pro.coins.ph, docs.coins.ph and doc.restapi.pdax.ph, and neither the desktop built-in browser nor Claude in Chrome was reachable. A full-text search of the Coins.ph REST and WebSocket docs found no mention of CORS, cross-origin access or geo-restriction; the only security behaviour mentioned is the WAF 403 ([coins-docs repo](https://github.com/coins-docs/coins-docs.github.io)). No CCXT issue reports CORS problems with coinsph ([ccxt issues](https://github.com/ccxt/ccxt/issues)). That is weak evidence, because CCXT users mostly run on servers. Whether Coins.ph blocks non-Philippine IPs, which matters for a user in Dammam, is also unverified.

The current code makes this matter on every platform. Static exports for html, Capacitor and Tauri call exchanges directly from the WebView. Capacitor 8 has CapacitorHttp switched off, so **CORS applies on Android and iOS today, not just on the web**. If a browser console `fetch('https://api.pro.coins.ph/openapi/quote/v1/klines?symbol=BTCPHP&interval=1h&limit=2')` returns data with `Access-Control-Allow-Origin`, the integration needs only a new CSP entry. If the request is blocked, each platform needs a different transport:

| Platform | If Coins.ph sends ACAO | If it does not |
|---|---|---|
| Web/PWA (Netlify) | Direct fetch; add host to `CONNECT_SRC` | Same-origin Netlify rewrite limited to the public paths; CSP stays `'self'` |
| Capacitor 8.6 | Direct WebView fetch | `CapacitorHttp.get()` gated on `Capacitor.isNativePlatform()`, called only from `packages/adapters` |
| Tauri v2 | Direct fetch; update `tauri.conf.json` CSP | `@tauri-apps/plugin-http` 2.8.3, with a capability scope of exact URL globs |

Each fallback has a cost that should go into the ADR. A Netlify rewrite is the documented config-only fix for "an API that doesn't support CORS", and requests are proxied "straight from our CDN servers" with a 26-second timeout ([Netlify Docs](https://docs.netlify.com/manage/routing/redirects/rewrites-proxies)). It adds a server-side hop the owner controls, however. Rate limits then fall on Netlify's edge IPs, which other sites share, and the docs say nothing about forwarding the client IP. With a 120/min budget that is a real risk of a 418 ban the user did not cause. CapacitorHttp is off by default. When it is on, it monkey-patches all fetches, and data crossing the bridge must be a string or JSON ([Capacitor Docs](https://capacitorjs.com/docs/v7/apis/http)). The 8.6.0 source shows GETs rewritten to a same-origin `/_capacitor_http_interceptor_` URL, so **the WebView CSP no longer enforces the host allowlist on mobile**. App code has to enforce it instead. The docs never actually state that CapacitorHttp bypasses CORS; that conclusion comes from the native execution path. Tauri's plugin is explicit: requests run in Rust and so are "not subject to CORS", and any URL outside the configured scope is rejected ([Tauri JS reference](https://v2.tauri.app/reference/javascript/http/)). It requires Rust 1.90 or later ([Tauri plugin docs](https://v2.tauri.app/es/plugin/http-client/)). Public CORS proxies are ruled out. They could read and alter every candle, which is a data-integrity risk for a signal engine, and they would put a third-party host in the CSP.

Error handling has to allow for the browser's opacity. A CORS block and a network outage look the same to JavaScript, which sees only that "an error occurred" ([MDN](https://developer.mozilla.org/docs/Web/HTTP/Guides/CORS/Errors/)). A 429 is visible only if the error response itself carries CORS headers. The native transports always see the real status and `Retry-After`. The adapter should therefore classify failures as blocked/unknown, throttled, WAF-blocked, server error or invalid payload. It should probe `/openapi/v1/time` once per session and mark the source `corsBlocked` rather than retrying it.

## The integration plan that keeps every app rule intact

The plan touches the code in five places, and each one respects an existing rule.

The first is the source and data layer. Add `coinsph` to `DATA_SOURCES` with its own `fetchCoinsphTickers` and `fetchCoinsphKlines`. Seed the symbol list once per session from `exchangeInfo`, cached in IndexedDB like the other per-source data. Pull tickers with `symbols` lists of at most 20, which costs weight 1, instead of the all-symbols call at weight 40. Reuse the Binance kline parser on indices 0–10, and page backfill with both `startTime` and `endTime`.

The second is pacing and bans. The current 120 ms per-source pacing works out to about 500 requests a minute, which is **four times Coins.ph's ceiling**. The source needs a token bucket set well below 120/min, roughly one request every 600 ms with jitter. That keeps a 10-pair × 4-timeframe scan, plus one ticker call, inside a single minute. The existing `RateLimitError` path already catches 429 and 418. Its 10-minute cooldown after a 418 is too short for bans that escalate to three days, so for Coins.ph a 418 should stop the source for the session and honour `Retry-After`. A 403 needs its own WAF class.

The third is the transport. Put all platform-specific HTTP code in `packages/adapters`, the only package allowed to import `@capacitor/*` or `@tauri-apps/*`. Gate CapacitorHttp by platform rather than enabling the global patch, so the Binance, Bybit and Bitget paths do not change and need no new regression testing. Pin `@tauri-apps/plugin-http` to the exact version, following the repo's exact-version rule.

The fourth is the allowlist. Coins.ph serves private and order endpoints from the same host as market data ([CCXT coinsph.js](https://github.com/ccxt/ccxt/blob/master/js/src/coinsph.js)). Every allowlist should therefore name paths, not just the host: `/openapi/quote/v1/*` plus `exchangeInfo`, `pairs`, `time` and `ping`, never `/openapi/v1/*` as a whole. ADR-0003 and release check R8 must cover every place a host now appears: `csp.ts` `CONNECT_SRC`, the duplicate CSP in `tauri.conf.json`, the Tauri capability scope with `scopeRedirects` enabled and `danger` never set, any Netlify rewrite, and a hard-coded in-code allowlist for the Capacitor native path. A new release check should fail the build if any Coins.ph path outside that set appears. It would apply the intent of R12 to the transport layer. The ADR should also ban Netlify signed proxies and custom proxy headers, the only features through which a secret could enter a credential-free build.

The fifth is scoring. Tag every series with source, symbol, quote currency and fetch time. Compute confluence separately per source, and present Coins.ph as a peso-premium and local-flow overlay.

Location matters in one more way. The SEC flagged Bybit and Bitget in August 2025, and PLDT and Globe then blocked their websites at the DNS level ([BitPinas](https://bitpinas.com/regulation/sec-flags-10/); [BitPinas](https://bitpinas.com/regulation/pldt-block/)). That has no effect from Saudi Arabia. If the terminal is used on a Philippine network, though, those two existing sources could fail to resolve; whether their API subdomains are blocked is unverified. Coins.ph, a BSP-licensed domestic venue, would keep working.

## Conclusion

The question changes once the evidence is in. It is no longer which Philippine exchanges to integrate, because there is exactly one. It becomes how to bring in a low-budget, CORS-uncertain, peso-quoted source without weakening the app's security model. The answer depends less on Coins.ph than on the terminal's own architecture. Once even one source needs native HTTP, the WebView CSP stops being the only enforcement point, so the allowlist has to move into code and release checks. That change will also benefit any future keyless source. Coins.ph's 120/min IP budget pushes the same way: a scheduler that treats each source's limit as a first-class setting will be needed for the next source too.

The work should be done in the order of its uncertainty. Run the browser-console CORS test, and repeat it from a Saudi IP, before writing any transport code, because the result decides whether this is a one-line CSP change or a three-platform adapter. Open `doc.restapi.pdax.ph` by hand once to confirm or overturn the PDAX exclusion. Then build Coins.ph as the peso-premium overlay its order books support. It is not a signal source on a par with Binance, and the 89% stablecoin share of its volume is the main reason.
