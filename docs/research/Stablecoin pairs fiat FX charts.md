# Discover quotes live, anchor fiat to central banks

For v2.7, the terminal should not hard-code stablecoin pairs. Each exchange's public metadata endpoint already lists its quote assets, so the app should read that list at runtime and filter it through a curated stablecoin allowlist. A live probe on 11 Nov 2026 counted these spot pairs by quote: Bybit **USDT 389, USDC 82, EUR 18, USD1 4, USDE 3, RLUSD 3, USD 3, XUSD 1**, and Bitget **USDT 3,595, USDC 31, EUR 11, USD1 6, USD 3, USDE 3, RLUSD 1, U 1**. Both exchanges also run USDC-settled perpetuals, whose symbols take the form `BTCPERP`. Binance is the exception. The probe could not read it, because its responses arrived without CORS headers, which fits a temporary IP ban. Its figures (USDT 400+, USDC 100+, FDUSD about 50, plus USD1, EURI and U) therefore rest on secondary sources. For each coin, indicators should run on **one primary pair**: the enabled, non-depegged quote with the highest 24h volume converted to USD. Liquidity from the other quotes should be summed in USD and shown as a separate column. Candles from different pairs should never be blended. For fiat display, the probe confirmed that **Frankfurter v2 is keyless and readable from the browser via CORS**. It blends official central-bank reference rates, applies peg overrides (SAR 3.75, AED 3.6725 and QAR 3.64 all came back exact) and shows which bank supplied each rate. The fawazahmed0 CDN is the fallback, and hard-coded official pegs are the last resort. Every price passes through an explicit stablecoin-to-USD factor, so a depeg appears as a warning and is not mistaken for a move in the coin. For the chart, a CSS pseudo-fullscreen overlay should be the base on every platform, because iPhones still cannot put a `<div>` into native fullscreen. Native or Tauri window fullscreen goes on top of that overlay, and pinch-zoom works on the visible range of bars (a data window), not on a CSS scale of the page.

## Exchanges already publish their stablecoin menus, so read them at runtime

Every venue names the quote asset as its own field, so the quote menu can be built from the data. The fields are Binance `quoteAsset`, Bybit `quoteCoin`/`settleCoin`, Bitget `quoteCoin`, and Coins.ph, which follows the Binance schema ([Binance Spot API docs](https://developers.binance.com/docs/binance-spot-api-docs/rest-api/general-endpoints); [Bybit v5 docs](https://bybit-exchange.github.io/docs/v5/market/instrument); [CCXT coinsph](https://docs.ccxt.com/exchanges/coinsph.md)). The live probe replaces the documentation-only guesses for Bybit and Bitget with measured counts:

The measured counts show three traps in a naive "group by quote" step. First, **`USD` and `EUR` show up as quote coins on both Bybit and Bitget, but they are fiat rails, not stablecoins.** A curated allowlist has to sort quotes into USD stablecoins, EUR stablecoins and fiat. The allowlist should cover USDT, USDC, FDUSD, USD1, U, USDE, RLUSD, XUSD, DAI, PYUSD, USDG and TUSD for USD, and EURI, EURC and EURQ for EUR. Anything not on it is either fiat or a crypto quote such as BTC, ETH or BNB. Second, **USDC-settled perpetuals on both Bybit and Bitget use symbols like `BTCPERP` and `1000PEPEPERP`.** Code that strips a "USDT" or "USDC" suffix from the symbol will silently drop them. The base must come from `baseCoin`, and the margin currency from `settleCoin` (Bybit) or `quoteCoin` (Bitget) ([live probe: Bitget USDC-FUTURES](https://api.bitget.com/api/v2/mix/market/contracts?productType=USDC-FUTURES)). Third, the quote set changes month to month. Binance moved its BUSD collateral to USD1. It pared back FDUSD margin pairs in January 2026 and ended FDUSD's zero taker fee on **29 Jan 2026**. It removed four USDC spot pairs on 18 Sep 2026, and it added "U"-quoted listings ([eco.com](https://eco.com/support/en/articles/13296290-7-best-stablecoins-on-binance-in-2026-ranked); [crypto.news](https://crypto.news/binance-to-remove-4-usdc-spot-pairs-on-sept-18/); [CryptoRank](https://cryptorank.io/news/feed/a377d-binance-adds-three-spot-trading-pairs)). Any list hard-coded today will be wrong by spring.

Binance needs its own resilience handling. The probe saw every CORS fetch to `data-api.binance.vision` fail. A `no-cors` request to the same host came back opaque, which means the host was reachable but sent no CORS headers. That pattern fits a rate-limit or ban response (418/429), and four days earlier the same PC had received Binance 200s. The practical consequence is that the browser hides the status code and any `Retry-After` header. The app sees only "Failed to fetch". It cannot tell a ban apart from an outage, so it has to back off without that information. The scanner should therefore keep an exponential backoff on Binance specifically. It should call exchangeInfo with `symbolStatus=TRADING&showPermissionSets=false` to shrink the 20-weight payload, cache metadata for hours, and read the live limits from the response's `rateLimits[]` ([Binance Spot API docs](https://developers.binance.com/docs/binance-spot-api-docs/rest-api/general-endpoints)). Binance also removed USDT, FDUSD, TUSD, USDP and DAI spot pairs for EEA users on **31 Mar 2025**. A keyless endpoint cannot know the viewer's region, so this belongs in an informational label, not a filter ([eco.com](https://eco.com/support/en/articles/13296290-7-best-stablecoins-on-binance-in-2026-ranked)). The data-api host serves spot only. Binance USDC-M perpetuals would need `fapi.binance.com`, which was neither probed nor verified against the docs.

## One primary pair per coin, with liquidity merged in USD

Every venue reports 24h turnover in the **quote** currency. BTC/EUR volume is in euros, BTC/FDUSD volume is in FDUSD and BTC/PHP volume is in pesos. Ranking or merging across quotes therefore needs one conversion step: `usdVolume = quoteVolume × px(quote→USD)`. The `px` term should come from the same venue's own stablecoin pairs (USDCUSDT, USD1USDT, USDEUSDT, EURIUSDT) multiplied by a USDT/USD factor, not from an assumed $1 ([Binance Spot API docs](https://developers.binance.com/docs/binance-spot-api-docs/rest-api/general-endpoints)). Bitget makes this easier on its futures tickers, which already carry a `usdtVolume` field next to `quoteVolume` ([live probe: Bitget USDC-FUTURES](https://api.bitget.com/api/v2/mix/market/contracts?productType=USDC-FUTURES)).

The merge rule follows from what indicators need. RSI, MACD, ATR and VWAP need real candles from a pair that actually traded. A volume-weighted blend of BTC/USDT, BTC/USDC and BTC/FDUSD candles invents highs and lows that never printed. It also turns any drift in the quote coin into a fake move in BTC, and it multiplies kline calls across N endpoints with misaligned timestamps. The recommended model has three parts. First, a **primary pair per (venue, base)**, chosen as the highest USD-converted 24h volume among the user's enabled quotes, excluding any quote currently flagged as depegged, with ties going to USDT. Second, an **aggregate USD liquidity column** that sums every enabled quote. Third, an optional **"list pairs separately" mode** keyed on `(venue, symbol)`, where each base/quote is its own row. The user's quote choice acts as a preference filter, not a hard requirement. If a coin has no USDC pair, it falls back to USDT with a visible quote badge instead of disappearing. This also covers the regulatory case: an EEA user can mark USDC as preferred and still see USDT-only coins, clearly labelled. Research on the October 2025 USDe event supports trusting multi-venue reference prices over any single thin order book ([21Shares](https://www.21shares.com//research/why-did-ethenas-stablecoin-remain-stable-onchain-but-depegged-on-binance)). Volume ranking across quotes is how the primary-pair choice applies that lesson inside one venue.

The rate-limit budget makes the same argument. Adding quotes is almost free for metadata and tickers. Bybit returns all 521 spot instruments in one unpaginated call, and one all-tickers call per venue covers every quote ([live probe: Bybit instruments-info](https://api.bybit.com/v5/market/instruments-info?category=spot&limit=1000); [Bybit v5 docs](https://bybit-exchange.github.io/docs/v5/market/instrument)). Klines are the expensive part, because they are fetched per symbol. Primary-pair mode costs N kline calls per scan, while separate mode costs up to N×Q. Bybit linear is the one metadata call that needs care: its 930 instruments span more than one page, so it must follow `nextPageCursor` and filter USDT-M from USDC-M on `settleCoin`, using `contractType=LinearPerpetual` to drop the 40 dated futures. Coins.ph remains the weakest link. Its quote set and field names were neither probed nor documented beyond CCXT's Binance-style method list, and its doc host now redirects to coins.xyz ([CCXT coinsph](https://docs.ccxt.com/exchanges/coinsph.md); [docs.coins.ph redirect](https://docs.coins.ph/xyz/rest-api)). The PHP/USDT/USDC set already in the app's code is the best evidence available.

## Frankfurter v2 passed the live CORS test and carries central-bank provenance

The probe settled what the documentation could not: which FX hosts a browser can actually read. All of the following returned 200 with acceptable CORS headers: **Frankfurter v2, Frankfurter v1, both fawazahmed0 hosts, open.er-api, ECB's SDMX data API, floatrates and CoinGecko's keyless `/exchange_rates`**. ECB's `eurofxref-daily.xml` failed for lack of CORS, and the old `api.frankfurter.app` host failed outright ([live probe: Frankfurter v2](https://api.frankfurter.dev/v2/rates?base=USD); [live probe: ECB eurofxref](https://www.ecb.europa.eu/stats/eurofxref/eurofxref-daily.xml)). A wildcard `Access-Control-Allow-Origin` accepts any origin on a request without credentials. That should cover the Tauri and Capacitor WebView origins as well as the static web build, though each shell still deserves a device smoke test.

Frankfurter wins on honesty, not just reach. It describes itself as keyless and free with "no quotas or monthly caps", drawing on official sources ([frankfurter.dev/llms.txt](https://frankfurter.dev/llms.txt)). With `expand=providers`, each rate lists the institutions that contributed to it, with their dates. On the probe day, PHP showed **BSP at 62.90 dated 2026-11-11** alongside ECB and others, and ARS listed BCRA and SAMA. Outliers carry `excluded:true` ([live probe: Frankfurter v2](https://api.frankfurter.dev/v2/rates?base=USD); [Frankfurter OpenAPI](https://api.frankfurter.dev/v2/openapi.json)). Frankfurter itself warns that blended rates are "Frankfurter's own calculation, not an official rate from any institution" ([frankfurter.dev/license](https://frankfurter.dev/license/)). The UI should therefore say "central-bank reference rates blended by Frankfurter", not "official rate". Where the probe conflicts with the docs, plan from the probe. The marketing figure is 219 currencies ([frankfurter.dev/llms.txt](https://frankfurter.dev/llms.txt)), but the live registry holds **161 fiat currencies**, and the currency picker should be built from `/v2/currencies` at runtime. The v1 endpoint carries only ECB's 29 currencies, with no SAR or AED, so v1 is not an option for a Gulf-based user.

The cross-source numbers also size the disagreement check. For PHP on 11 Nov, the sources gave **BSP 62.90, the Frankfurter blend 63.00, fawazahmed0 on jsDelivr 62.949 (dated 11-10) and the pages.dev mirror 63.164 (dated 11-11)**. That is a 0.42% spread on a quiet day ([live probe: Frankfurter v2](https://api.frankfurter.dev/v2/rates?base=USD); [live probe: pages.dev](https://latest.currency-api.pages.dev/v1/currencies/usd.min.json)). A "sources disagree" flag at 0.5% for major currencies and 2% for minor ones would stay silent here and fire on real divergence. These thresholds are design defaults; no industry standard was found. The jsDelivr copy ran a day behind its own mirror, so the fallback should fetch both and keep whichever reports the newer `date`, instead of trusting the documented host order. Frankfurter sends `cache-control: max-age=64725, stale-if-error=86400`, which is about 18 hours of browser caching plus a day of grace on errors ([live probe: Frankfurter v2](https://api.frankfurter.dev/v2/rates?base=USD)). A 6-hour app refresh therefore needs `fetch(url, {cache:'no-cache'})` to revalidate, or it will keep reading the cached copy. The `connect-src` additions are `https://api.frankfurter.dev https://cdn.jsdelivr.net https://latest.currency-api.pages.dev`. Rates are fetched at runtime and never baked into the static export, which avoids any redistribution question.

## Pegs, official-only regimes and stablecoin depegs each get a label

An honest display depends on telling the user what kind of number they are looking at, so each currency needs one of four badges. Hard pegs get **"official peg"**. The GCC pegs are SAR 3.75, AED 3.6725, QAR 3.64, OMR 0.3845 and BHD 0.376 ([MEED](https://www.meed.com/gcc-to-defend-currency-pegs/)). Frankfurter returned the first three exactly, because its "pegged-currency rows… come from the peg, not provider data" ([live probe: Frankfurter v2](https://api.frankfurter.dev/v2/rates?base=USD); [frankfurter.dev](https://frankfurter.dev/)). The floatrates value of 3.7515 for SAR shows what happens when a source ignores the peg. KWD (0.3093 live) is tied to an undisclosed basket and should not be presented as a fixed peg. HKD gets **"managed band"**: it trades inside the 7.75–7.85 Convertibility Zone, and it sat at 7.8488 on probe day, near the weak side ([HKMA](https://www.hkma.gov.hk/eng/key-functions/money/linked-exchange-rate-system/how-does-the-lers-work/)). Currencies with multiple official rates get **"official central-bank rate"**, with a tooltip saying market rates may differ. These include ARS at 1,546.23 via BCRA and NGN at 1,347.37 via CBN ([live probe: Frankfurter v2](https://api.frankfurter.dev/v2/rates?base=USD); [Frankfurter providers](https://frankfurter.dev/providers/)). No source in this research quantified the current parallel-rate gaps, so the app should state that a gap may exist without putting a number on it. Free floats get **"reference mid-rate"**. The peg values, and only the peg values, should ship in the bundle as an offline fallback. That keeps SAR conversion working with no network at all.

The conversion chain should spell out the stablecoin leg instead of hiding it: `price_in_quote × quote→USD × USD→fiat`. CoinGecko itself does not treat USDT as equal to USD. It routes USDT- and USDC-quoted tickers through an internal USD on-ramp index before applying fiat rates ([CoinGecko methodology](https://www.coingecko.com/en/methodology)). The terminal can source the USDT/USD factor without adding a host. Frankfurter's own USDT row read **1.0013 per USD on 2026-11-10**, and fawazahmed0 read 1.00142, which puts USDT about 0.13% below a dollar ([live probe: Frankfurter v2](https://api.frankfurter.dev/v2/rates?base=USD); [live probe: jsDelivr](https://cdn.jsdelivr.net/npm/@fawazahmed0/currency-api@latest/v1/currencies/usd.min.json)). Frankfurter does not say which provider supplies its crypto rows, so the tooltip should name the factor and its date. Any other stablecoin's factor comes from the venue's own pair against USDT. A simpler "USDT treated as USD" mode is still honest if the label says so.

Depeg handling has to be built in, because recent history has several cases. **FDUSD fell about 9% on 2 Apr 2025**, at a time when BTC/FDUSD was Binance's most-traded pair ([The Block](https://www.theblock.co/post/349289/fdusd-stablecoin-depegs-9-after-justin-sun-raises-concerns-over-first-digital-solvency)). **USDe printed $0.65 on Binance spot for about 40 minutes on 10 Oct 2025** while holding near $1 on Curve ([21Shares](https://www.21shares.com//research/why-did-ethenas-stablecoin-remain-stable-onchain-but-depegged-on-binance)). USDE/USDT on Binance hit **$0.9202 for seconds on 22 Sep 2026** ([KuCoin blog](https://www.kucoin.com/blog/usde-depeg-binance-0-92-1011-contagion-risk)). USDE trades as a quote on both Bybit and Bitget today, so the risk sits inside the scanner's own universe. The proposed tiers are design defaults, not an industry standard. **Watch** applies when the 1-minute close is at least 0.5% off peg for 5 or more minutes, **warn** at 1%, and **severe** at 2% or on any 5% one-minute wick. A second venue must confirm before the app shows "depeg", because venue-local wicks are common. A flagged quote drops out of primary-pair selection and aggregate volume, and every price shown in that quote carries a warning chip, so that a BTC/FDUSD spike is not read as a BTC rally. Euro stablecoins compare against EUR/USD from Frankfurter rather than $1. Coins.ph USDT/PHP set against BSP's rate can power an optional, labelled **"market (USDT) rate"** that shows the local premium. It must never be the default honest rate. Formatting uses `Intl.NumberFormat` with `style:"currency"`. That applies the ISO minor units automatically: zero decimals for JPY, three for KWD, BHD and OMR. Crypto prices need overridden `maximumSignificantDigits`, because ISO minor units truncate sub-cent tokens. The constructor should sit in a try/catch, since older WebKit rejected `currencyDisplay:"narrowSymbol"` ([MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/NumberFormat/NumberFormat); [WebKit bug 226297](https://bugs.webkit.org/show_bug.cgi?id=226297)). Every rate needs a footer chip such as "Rates: central banks via Frankfurter · as of 2026-11-11 · USDT 0.9987", with an amber badge once the rate is more than 3 days old.

## Pseudo-fullscreen first, native fullscreen second, data-window zoom everywhere

Native element fullscreen cannot be the foundation, because iPhones refuse it. caniuse lists iOS Safari as "Partial support" through 27.2, and developers report that `webkitEnterFullScreen` works for `<video>` but not for a `<div>` ([caniuse](https://caniuse.com/mdn-api_element_requestfullscreen); [Apple Developer Forums](https://developer.apple.com/forums/thread/133248?page=3)). Android WebView, which is what Capacitor Android uses, reports fullscreen as unsupported unless the native app overrides `WebChromeClient#onShowCustomView` ([Chromium: WebView full screen](https://chromium.googlesource.com/chromium/src/+/main/android_webview/docs/full-screen.md)). The design therefore uses one `useChartFullscreen()` hook with three tiers.

**Tier 1, always on: a CSS overlay.** It uses `position:fixed; inset:0; height:100dvh`, padding from `env(safe-area-inset-*)` (which requires `viewport-fit=cover`), a body scroll lock, `overscroll-behavior:contain`, a focus trap and a `ResizeObserver` that redraws the canvas at `devicePixelRatio`. This tier is the only one that works on iPhone and Capacitor iOS. **Tier 2: `requestFullscreen()` where `document.fullscreenEnabled` is true**, which covers desktop browsers and Android Chrome. The call happens inside the click handler, its rejection is caught, and `fullscreenchange` is listened to so that the browser's own Esc also exits the overlay. **Tier 3, Tauri: window-level fullscreen** via `getCurrentWindow().setFullscreen()`. This needs `core:window:allow-set-fullscreen` added to the capability file, because that permission is not in `core:window:default` ([Tauri v2 core permissions](https://v2.tauri.app/reference/acl/core-permissions/)). The window route is preferable to fullscreen requested from inside the webview, because the webview engines behave inconsistently. Reports include WKWebView fullscreen being unreliable on iPadOS and leaving the Dock hidden on macOS 27, and frameless (`decorations:false`) Tauri windows breaking macOS fullscreen ([Apple forums 766736](https://developer.apple.com/forums/thread/766736); [Apple forums 846037](https://developer.apple.com/forums/thread/846037); [tauri-ui #4](https://www.github.com/agmmnn/tauri-ui/issues/4)). The F11 menu item and the chart button should call the same command. On Android, the hardware back button must close chart fullscreen before it navigates. In the web build, pushing a history state when the overlay opens lets the browser's back gesture close it. Landscape lock through `@capacitor/screen-orientation` is a convenience only: it does nothing on large screens on Android 16+ with targetSdk 36, and iPad needs `UIRequiresFullScreen` ([Capacitor Screen Orientation](https://capacitorjs.com/docs/apis/screen-orientation)). A "rotate for more bars" hint plus responsive reflow is the better default.

Pinch-zoom should change the data window, not the CSS scale. The hand-built chart already has a visible-range model for arrow keys and the 60/250/1000/all selector. The gesture module (about 200 lines) maps onto that model. It tracks pointers in a `Map<pointerId,{x,y}>` with `setPointerCapture`. One finger pans, at `dBars = dxPx / barWidthPx`. Two fingers zoom: the span scales by `dist0/distNow` and is anchored at the bar under the pinch midpoint, clamped between roughly 10 bars and the loaded total. Replay mode caps the end of the window at the replay cursor. The plot sets `touch-action:none` in fullscreen and `pan-y` inline, so the detail sheet still scrolls vertically. A desktop trackpad pinch arrives as a `wheel` event with `ctrlKey`, which is handled through a `{passive:false}` listener that calls `preventDefault` only when it acts on the event. Redraws are coalesced through `requestAnimationFrame`, and a double-tap resets the view. The page-wide `user-scalable=no` stays out, because it breaks the user's ability to zoom the page for readability. Every multi-touch gesture also needs a single-pointer equivalent: + / − / Reset / Full screen buttons at least 44 px, keyboard `+`, `−`, `Home`, `End`, Shift+arrow pan, and an `aria-live` readout such as "Showing 120 bars, 3 Oct – 10 Nov". TradingView Lightweight Charts v5.2.1 (Apache-2.0) offers pinch and pan out of the box through `handleScale.pinch` and `handleScroll`. Adopting it would mean rebuilding the VWAP, Bollinger and MACD panels and replay on its API, and it shows an attribution logo by default ([CSS Script summary](https://www.cssscript.com/financial-chart/)). Its compatibility with a strict `style-src` policy is also unverified. Extending the existing chart is the better trade for v2.7. Gestures can be tested with two-point CDP touch events in Playwright's Chromium. Native fullscreen in WebView2, WKWebView, WebKitGTK and Android WebView still needs manual checks on each device.

## Conclusion

The three features turn out to be one problem in three places: being explicit about units. A stablecoin quote is a unit that can drift, a fiat rate is a unit with a source and a date, and a chart zoom acts on bars, not pixels. The terminal should make each of those factors visible instead of folding them into a single number. The probe also changed two plans. It confirmed that Frankfurter v2 is readable from the browser, which keeps the whole FX layer keyless and backend-free inside the existing CSP model. It also showed that Binance's ban responses arrive without CORS headers, so the browser cannot tell a ban apart from an outage, and Binance needs a backoff policy that the other venues do not.

The remaining risk sits in untested sources, not in the architecture. Coins.ph's quote list and field names, Binance's live counts and its USDC-M perpetuals, which provider supplies Frankfurter's USDT row, and native fullscreen inside each shell's webview were all unverified at writing. A small in-app diagnostics panel would close most of these gaps. It would show per-venue quote counts, the provenance chip for each FX rate and the result of each CORS probe. It would also turn the next live probe from a manual exercise into a feature the owner can check at any time.
