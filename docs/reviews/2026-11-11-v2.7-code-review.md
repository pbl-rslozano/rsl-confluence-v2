## 1. Important: the chart Focus view is trapped inside the detail dialog  **[run]**

**Where**
- `components/price-chart.tsx:532–537`: the frame becomes `fixed inset-0 z-[200]` with `height:100dvh; width:100vw`.
- `components/ui/dialog.tsx:68`: `DialogContent` has `fixed … translate-x-[-50%] translate-y-[-50%]`. With Tailwind 4.3.3 this is the CSS `translate` property.
- `app/page.tsx:1781`: the detail sheet adds `max-h-[92dvh] overflow-y-auto overflow-x-hidden`.

**Failure:** any `translate`/`transform` other than `none` creates the containing block for `position: fixed` descendants. The Focus view is therefore laid out against the dialog box, not the viewport. Because the dialog also scrolls and clips, the frame:
- starts at the dialog's top-left corner,
- moves up by the dialog's scroll offset, and
- is clipped by the dialog's overflow.

This was reproduced in Chromium with the same CSS (dialog 900 px wide, centred, scrolled by 600 px):

```
chart rect = x 217, y −584, 1366×800   (should be 0,0,1366×800)
elementFromPoint(10,10) = BODY          (the chart does not cover the viewport)
```

The Focus view is the **only** full-screen path in these cases:
- in Tauri and Capacitor (`canUseNativeFullscreen` returns false when a shell hook exists),
- on iPhone/iPad Safari,
- whenever `requestFullscreen` rejects.

So WP14.3 rows 2–3 do not work, and the user-guide claim (en.md:192, "fills the app window") is false there. On desktop, Tauri does make the *window* full screen, but the chart stays a clipped box inside the sheet.

Acceptance CH-5 runs in Chromium, which takes the native Fullscreen API path (the top layer ignores ancestor transforms), so it cannot catch this.

**Fix (any one of these)**
- Render the full-screen frame through `createPortal` into the Radix dialog's portal container, as a sibling of `DialogContent`. Mark it with `data-radix-…`, or `onPointerDownOutside={e => e.preventDefault()}` while full, so Radix does not treat it as an outside click.
- While `full === "focus"`, put `translate: none; transform: none; overflow: visible` on the `DialogContent`. This needs a callback prop or a `data-chart-full` attribute plus a CSS rule.

Add an acceptance variant that forces the Focus path (e.g. stub `document.fullscreenEnabled = false`) and asserts the frame's rect equals the viewport.

## 2. Important: display currency USD never loads rates, so Coins.ph / EUR scans are stuck on "No rate for USD yet"

**Where:** `app/page.tsx:657–675`, especially `664`: `if (displayCurrency === "USD" && !cached) return;`. Also `1111–1112` (`priceCurrency` falls back to native) and `2336–2337`.

**Failure:**
1. Fresh install, browser language `en-US`, so *Auto* resolves to USD (#7).
2. Choose **Coins.ph**.
3. The native currency is PHP and the display currency is USD, but the effect never fetches because the *display* currency is USD. `fx` stays `null`, and `convert(1,"PHP","USD",null)` is NaN (PHP is not a built-in peg), so `priceCurrency` = PHP.
4. Result: the grey line reads **"No rate for USD yet — showing PHP"** permanently. The Coins.ph "USDT is x % against the official peso rate" note (`impliedUsdtPremiumPct` needs `fx`) never appears, although the guide (en.md:262) promises it.

The same happens for a Binance **EURI** scan (native EUR) with display USD. It only "fixes itself" if the user once picked a non-USD currency, which leaves a cached table.

**Fix:** fetch when `displayCurrency !== nativeCurrency`, or whenever the native currency is not USD (`scanMeta.currency`), not only when the display currency is not USD. Add `nativeCurrency` to the effect's dependencies.

## 3. Minor: the rate line labels the wrong currency

**Where:** `app/page.tsx:2336–2350` (`FxInfoLine`). `fx.info` = "Prices in {code} · 1 USD = {rate} {code}".

| native → display | What is shown | What is true |
|---|---|---|
| PHP → USD (rates cached) | `ref = native` → **"Prices in PHP · 1 USD = 63 PHP"** | the table shows `$…` |
| EUR → EUR (EURI scan, display EUR) | "Prices in EUR · 1 USD = 0.89 EUR · reference rate · Frankfurter" | nothing was converted |
| PHP → SAR | "Prices in SAR · 1 USD = 3.75 SAR · official peg (SAMA)" | the conversion also used the PHP rate, which is not shown and is the non-peg leg |

This works against WP13.3 "honest labelling".

**Fix:**
- Say "Prices in {shown}".
- When `native !== "USD" && native !== shown`, show both legs ("1 USD = 63 PHP · 1 USD = 3.75 SAR"), or the direct cross ("1 PHP = 0.0595 SAR").
- Print no rate when `native === shown`.

## 4. Minor: depth "All saved" resets zoom/pan on every new bar; a backfill shifts a panned view

**Where:** `app/page.tsx:1863` (`visible={chartDepth === "all" ? detailAsset.klines.length : …}`) and `components/price-chart.tsx:131–136`.

**Failure:**
- In "All" mode `visible` *is* `total`. Each auto-refresh that appends a candle changes `visible`, so the `seen.visible !== visible` branch runs `setView(initialView(total, visible))`. The user's zoom (say 50 bars) jumps back to all bars every refresh, and the "keep following the newest bar" logic is never used in this mode.
- In the other depths, "Load 5K older" *prepends* bars while `view.end` stays an index. A view panned into the past (`end < seen.total`) then shows bars about 5,000 positions older than before.

**Fix:**
- Pass the depth intent (`"all"` or a number) rather than a length, and treat "all" as `count = total` only on a real depth change.
- When `klines[0].time` changes and the view is not following, shift `end` by the number of prepended bars (or keep the view as `{endTime, count}`).

## 5. Minor: a scroll gesture counts as a tap (inspect, and double-tap reset)

**Where:** `components/price-chart.tsx:630` (`onPointerCancel={onPointerUp}`) and `489–497`.

**Failure:** with `touch-action: pan-y`, a vertical swipe that starts on the chart makes the browser take over, which fires `pointercancel`. `onPointerUp` sees `kind === "drag" && !moved` (dx < 6 px) and handles it as a tap: it calls `hoverAt` and stamps `lastTap`. Two quick scroll flicks over the chart within 320 ms call `resetView()` and discard the user's pinch-zoom. Scrolling the sheet past the chart is the most common phone gesture there.

**Fix:** give `pointercancel` its own handler that only clears the pointer and gesture (no tap and no `lastTap`). Also count a tap only if the pointer was down for less than about 300 ms and moved under 6 px in both axes.

## 6. Minor: `baseFromInput` turns `DOTUSD` into `DO`  **[run]**

**Where:** `lib/quotes.ts:117–119, 127–131`. It is used by `market-client.ts:575` (`normalizeAssets`), `app/api/market/all/route.ts:64` and `preferences-store.ts:91`.

**Failure:** stablecoin suffixes are tried before plain `USD`, and `TUSD` is one of them. Any `<base ending in T>USD` therefore loses its T:

```
splitPair("DOTUSD")  → {base:"DO",  quote:"TUSD"}
splitPair("USDTUSD") → {base:"USD", quote:"TUSD"}
```

Typing `DOT/USD`, `FET-USD`, `GRTUSD` or `BATUSD` into **Watch** scans nothing for that coin, and the entry is saved as `DO`. v2.6's `/[-_/\s]?(USDT|USD|PHP)$/` gave `DOT`. This is a USDT-mode behaviour change (SQ-1).

Bare tokens that end in a code are also cut (`XDAI` → `X`, `SUSD` → `S`), but those are rarer.

**Fix:**
- For *user input* without venue metadata, try `USDT`/`USDC`/`USD` first, and accept a longer stablecoin suffix only when a separator was typed (`ETH/FDUSD`) or the venue metadata knows the symbol.
- Alternatively, prefer `USD` over `TUSD` when `s.slice(0,-3)` is a known base.
- Add `DOTUSD` and `DOT/USD` to the SQ-2 golden.

## 7. Minor: *Auto* display currency is a language guess, not the device region  **[run]**

**Where:** `lib/fx-rates.ts:175–186`, which uses `navigator.languages` and `new Intl.Locale(tag).maximize().region`.

**Results:** `ar` → **EGP**, `en` → USD, `ur` → PKR, `pt` → BRL, `en-SA` → SAR.
- A user in Saudi Arabia whose phone or PC language is English (`en-US` / `en-GB`) gets USD or GBP.
- One using plain Arabic `ar` gets Egyptian pounds.

The guide (en.md:65, 258) says "your device region's currency (Saudi Arabia → SAR …)".

**Fix:**
- Use `Intl.DateTimeFormat().resolvedOptions().timeZone` → region (e.g. `Asia/Riyadh` → SA) as the region signal. It is local, not IP-based.
- Use a language tag only when it carries an explicit region, and never `maximize()` a bare language.
- Otherwise make the guide say "your system language's region".

## 8. Minor: depeg coverage and "≈" are weaker than documented

**Where:** `lib/market-client.ts:332–335` (USDT mode returns `depeg: []`), `349–355`, `361`; `app/page.tsx:1537–1543`.

- **USDT mode (the default) never produces a depeg banner.** In USD/USD display the rate line is hidden too, so USDT/USD is never shown. en.md:121 says the banner covers "the stablecoin you scan in".
- **USDC perps:**
  - Bybit `linear` and Bitget `USDC-FUTURES` lists contain no `USDCUSDT`, so `usdtPer("USDC")` is undefined. There is no depeg reading, and **every** row is pushed to `approx` (shown as "≈").
  - On Bitget the "≈" is wrong, because `qvUsd` is then overwritten with the venue's `usdtVolume`.
- **Attribution:** a reading is "USDC price in USDT". If USDT itself trades at $0.98, the banner says "USDC is +2.04 % from its peg on this exchange". `DepegReading.reference` is dropped in the UI.

**Fix:**
- Show the reference in the banner ("USDC/USDT +2.04 %").
- Add a USDT reading from `fx.usdtPerUsd` (the table already has it) when it is ≥ 0.5 %.
- For perps, read the spot `USDCUSDT` once from the same venue, or say "no reference on this market".
- Do not add a symbol to `approx` when its volume came from `usdtVolume`.

## 9. Minor: the main chart's axis labels can duplicate again (review #9)  **[run]**

**Where:** `components/price-chart.tsx:288` uses `formatAxisTicks` only when `formatAxis === fmtAxis`. `app/page.tsx:1115–1119, 1861` always passes `chartAxis`, which formats each tick on its own (`toFixed(2)+"k"` for 1,000–99,999).

**Example:** ETH on 1m with a 3,000–3,004 range gives `3.00k 3.00k 3.00k 3.00k 3.00k`, and BTC around 100,050 gives `100.0k ×3`. The distinct-label fix only reaches `ChartReplay`.

**Fix:** convert the tick values first and then run `formatAxisTicks` on the converted array (it already handles any magnitude). Use `chartAxis` only to map a value into the display currency.

## 10. Minor: closing the chart forces the desktop window out of full screen

**Where:** `components/price-chart.tsx:192` (`useEffect(() => () => shellFullscreen()?.set(false), [])`) and `packages/adapters/tauri/index.js:42`.

**Failure:**
1. The user puts the desktop app in full screen (View → Full screen, F11 or the macOS green button).
2. They open a detail sheet, then close it or toggle **Open chart replay** (which unmounts `PriceChart`).
3. `getCurrentWindow().setFullscreen(false)` runs and the window leaves full screen.

On Capacitor the same call runs `StatusBar.show()` on every sheet close.

**Fix:** track whether *this* chart turned the shell full screen (a ref set in `enterFull` and cleared in `exitFull`), and call `set(false)` on unmount only in that case.

## 11. Minor: `risk-engine.baseOf` ignores the source  **[run]**

**Where:** `lib/risk-engine.ts:171–174, 185, 297`. `usdQuoted` does take `src` (line 178).

**Failure:** quotes recognised only from venue metadata (registry `suffix:false`: `U` on Binance and Bitget) give `baseOf("BTCU")` = `BTCU`. A `BTCU` proposal therefore:
- passes the new per-base duplicate rule next to an open `BTCUSDT`, and
- is clustered as `crypto-alt` instead of `crypto-major`.

`currency` is correctly approved.

**Fix:** `baseOf(pair, src)` → `splitPair(pair, src)`, and pass `x.src` / `p.src` at lines 185 and 297. Positions already carry `src`.

## 12. Minor: R21 can pass falsely

**Where:** `tools/checks/display-only.mjs:39, 44–47`.

**Gap:**
- Only direct `from "…fx-rates"` / `import("…fx-rates")` in the `BOUNDARY` file list is detected.
- A boundary module that imports a helper which imports `fx-rates` (for example a future `money.ts` → `fx-rates.ts`) passes.
- A side-effect `import "./fx-rates"` passes.
- `market-client.ts` imports `quotes.ts`, which today is clean but is not on the list.

**Fix:** resolve imports transitively from each boundary file. It is a small walk over relative specifiers in `src/lib`.

## Verified correct (no finding)

- **USDT mode identity (SQ-1).** For Binance, Bybit (spot and linear) and Bitget (spot and USDT-FUTURES), the v2.7 path is the same as v2.6:
  - same filter (`endsWith("USDT")`), with the USDC-settled exclusion inert for USDT symbols;
  - same `||0` volumes and same stable descending sort;
  - same raw `quoteVolume` strings and same request set (no `exchangeInfo` / spot `symbols` call).
  - Only additive response fields were added. The exception is monitor input, see #6.
- **Volume conversion.** Binance and Bybit convert quote-coin volume at the venue's `XUSDT` price. Bitget's `usdtVolume` is *not* converted twice (loop at `market-client.ts`, Bitget fetcher). Best-mode selection uses `usdtVolume × rate` before that override, but the error is at most the stablecoin's deviation, far inside the 25 % hysteresis.
- **NaN handling.** `byUsdDesc` and `selectPairs` rank NaN volumes last. A NaN `quoteVolume` string reaches the UI as "—".
- **Best hysteresis.** The key is `${source}:${base}`, so there is no cross-source leak. A delisted previous pick falls through. Note: in the server-proxy deployment the map is per process (serverless instances do not share it), so hysteresis is best-effort there.
- **Classification.** `classifySymbol`'s USDT-twin recursion terminates (the twin always ends in `USDT`): `EURIUSDC` → fx, `FDUSDUSDC` / `USDCUSDT` → excluded, `PAXGUSDC` → commodity, `BTCPERP` → crypto.
- **USDC perps.** Bybit `settleCoin` is used as the quote, and `bitgetProductOf` (`…PERP` → `USDC-FUTURES`) is safe: no USDT-FUTURES symbol ends in `PERP`.
- **FX math.** `convert` is `value / perUsd(from) × perUsd(to)`, with "units per USD" (PHP→SAR checked). Pegs are used as a fallback, validation is finite and > 0 with ISO codes, and `localStorage` reads and writes are wrapped. `formatMoney` gives `$`, `€`, `₱`, `SAR `, `KWD 64,250.500`, `¥64,251`, and a sign before the symbol.
- **page.tsx hooks.** No early return before hooks. The `load` dependency arrays include `quote`, so one render gives one scan when source and quote change together. `currentScanRef` is written after every commit, before any user click can run, so the backfill guard compares against the header correctly. History aborts on a source/timeframe change.
- **Chart.** Memo dependencies are complete (`layers` depends on `model`, `showVolume`, `viewW`, `chartW`; `model` on `hidden`, `periods`, size and `formatAxis`, which is a stable `useCallback`). Decimation keeps true OHLC, and overlay/MACD sampling uses bucket-end indices into arrays aligned with the full series (`macdHistogram` length equals the number of klines). The hover index is clamped. Esc capture on `window` runs before Radix's document listener, including Android Back's synthetic Esc. Body overflow is restored. The full-series indicator recompute costs about 2.3 ms at 10k bars per view change **[run]**.
- **CSP and R8.** `next.config.ts` → `csp.ts` → `public-hosts.ts` loads under Next 16.2.10. R8 now checks table ⇔ desktop CSP parity and ADR naming. R6 is token-wise. `check-egress` reads the table.
- **Paper.** `bybit-perp BTCUSDT` and `bitget-perp BTCPERP` are approved by `paper.rule.currency`. Coins.ph is refused, as documented (en.md:404). The duplicate rule by base works for `BTCUSDT` / `BTCUSDC` / `BTCPHP`.

## Summary

The v2.7 data-layer work is solid:
- USDT mode really is v2.6 (apart from the `TUSD` input parse, #6).
- The quote and volume arithmetic, FX conversion and release-check refactor are correct, and all unit tests pass.

The two Important defects are in the user-facing parts:
- **#1** The Focus view is laid out relative to the transformed, scrolling detail dialog. Full screen does not work on iPhone/iPad, in the Android/iPhone apps or in the desktop app. Chromium acceptance cannot see it, because it uses the native Fullscreen API.
- **#2** With display currency USD (the *Auto* default on English systems), rates are never fetched. Coins.ph and EUR-stablecoin scans show a permanent "No rate for USD yet" line, and the Coins.ph USDT-premium note never appears.

Fix #1 and #2 before merge. The ten Minor items (labelling, *Auto* region, chart view stability with "All saved" and touch scrolling, duplicate axis labels, the depeg and "≈" gaps, shell full-screen cleanup, `baseOf` source, R21 transitivity) can go in the same PR or be listed for v2.8.
