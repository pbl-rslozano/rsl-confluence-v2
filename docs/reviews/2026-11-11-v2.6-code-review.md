## 1. Important: PriceChart crashes when the hover index outlives the slice  **[run]**

**Where:** `apps/confluence/web/src/components/price-chart.tsx:82, 236–237, 299–302, 458–463`. There is no `error.tsx` or error boundary anywhere under `src/` (grep for `ErrorBoundary|componentDidCatch|getDerivedStateFromError` finds nothing).

**Failure:** `hoverIdx` is an index into `slice = klines.slice(-visible)`, and it lives in state. It is not cleared when `visible` or `klines` change, and it is only reset by `onMouseLeave`. Keyboard navigation (`ArrowLeft/Right/Home/End`) sets it and never clears it on blur. The tooltip readout dereferences `hover.time` without a guard (only the crosshair has `hover &&`).

Steps to reproduce:
1. Set chart depth to **1K bars**.
2. Focus the chart and press Home, then the arrow keys (hoverIdx = 500).
3. Shift+Tab to the depth select and choose **60 bars**.
4. `slice[500]` is `undefined`, `fmtTime(hover.time)` throws, and React unmounts the whole app (Next shows "Application error").

Reproduced on a scratch transpile with the initial hover forced to 500 and `visible=60`:
`CRASH with hoverIdx=500, visible=60: Cannot read properties of undefined (reading 'time')`.

v2.7 relevance: pinch-zoom/pan changes `visible` and the window offset continuously, which turns this from rare into routine.

**Fix:**
- Store the hovered **bar time** rather than an index. Derive `activeIdx = slice.findIndex(...)` and fall back to the last bar.
- Or at minimum clamp: `const activeIdx = Math.min(hoverIdx ?? slice.length - 1, slice.length - 1)`. Guard the readout with `hover &&`, and reset `hoverIdx` in an effect on `[visible, klines.length]` and on `onBlur`/`onPointerLeave`/`onPointerCancel`.
- Add `app/error.tsx` or a boundary around the detail sheet so a panel failure cannot blank the scanner.

## 2. Important: backfill, replay and perp panels act on stale rows from another source or timeframe

**Where:** `apps/confluence/web/src/app/page.tsx:921–968` (`backfillHistory` uses the closure's `dataSource`/`timeframe`), `953` (save), `1719`, `1733–1735` (replay `src: dataSource`), `1755–1756` (perp panels gated on `dataSource`). Rows are only cleared at `652` (profile change) and `669` (watchlist mismatch), never on a source or timeframe change. `history-store.ts:27–29` keys series by `${source}:${interval}:${symbol}`.

**Failure:**
1. The user switches Binance → Bybit Spot. The Binance rows stay on screen until the Bybit scan finishes (or forever, if it fails, e.g. Coins.ph blocked on a foreign web host).
2. The user opens `BTCUSDT` and clicks **Load 5K older**.
3. `fetchHistory("bybit-spot", "BTCUSDT", …, endTime = oldestBinanceBar-1)` runs. Then `saveHistoricalSeries("bybit-spot", tf, "BTCUSDT", mergeKlines(binanceKlines, bybitOlder))` persists Binance bars under the Bybit key.
4. Later scans merge that store (`page.tsx:704–710`). The overlap is overwritten, but older Binance bars stay contiguous and are scored, logged to the ledger and replayed as Bybit data.

The same thing happens across timeframes: switch 4h → 1h and backfill a 4h row, and 4h bars plus older 1h bars land under the 1h key. Replay paper trades opened from such a row are labelled with the wrong `src` (wrong cost model). The derivatives and order-flow panels query Bybit perp for a row scored on another venue.

**Fix:** carry `src` and `tf` on `AssetRow` (set in `load`) and use `asset.src`/`asset.tf` everywhere the detail sheet acts. Also, either clear `rows`/`detailAsset` in an effect on `[dataSource, timeframe]`, or disable row actions while `scanMeta.source !== dataSource`. As defence in depth, have `backfillHistory` refuse when `asset.src !== dataSource`. This becomes more important in v2.7: with per-exchange quote selection, a quote change is another "source change" that must reset rows and detail.

## 3. Important: the paper book mixes PHP and USDT; BTC on Coins.ph is an "alt"  **[run]**

**Where:** `lib/risk-engine.ts:170–171` (`baseOf`), `175–177` (`clusterOf`), `286–287` (cluster and duplicate rules), `303–307` (sizing and leverage room in account units). `lib/paper-broker.ts:210–220` (one book; notional = `size × entry` in the pair's quote). The UI label `i18n/en.json:332` says "Starting equity (USDT)". `paper-dialog.tsx` does not gate on source.

**Failure:** the risk budget is in USDT, but `stopDistance`/`entryRef` for Coins.ph are in PHP.

```
BTCUSDT size 0.01666   risk 49.98        notional 1666
BTCPHP  size 0.0002873 risk 49.99 (PHP)  notional 1666 (PHP) ≈ $29
```

The "1 % risk" on a Coins.ph pair is really about ₱50 (about $0.86), but it is booked as 49.99 USDT. P&L in PHP is added to a USDT balance. Leverage room and open-risk sums add PHP and USDT numbers together.

`baseOf("BTCPHP") = "BTCPHP"`, so BTC/ETH on Coins.ph are clustered as `crypto-alt`. The duplicate rule compares whole pairs, so `BTCUSDT` (Binance) and `BTCPHP` (Coins.ph) are both allowed: the same exposure, twice.

v2.7 makes this worse: `baseOf("BTCFDUSD") = "BTCFD"`, `baseOf("ETHUSD1") = "ETHUSD1"`, `baseOf("BTCEUR") = "BTCEUR"`, all clustered as alts, while EUR-quoted P&L lands in a USDT book.

**Fix:** give each position a `quoteCcy`. Convert entry, stop, notional and P&L into the account currency at an FX rate fixed at fill time (record the rate on the journal row). Alternatively, block proposals whose quote ≠ account currency until conversion exists. Derive the base from venue metadata (see #4), not a suffix regex. Make the duplicate and cluster rules key on the base asset.

## 5. Important (for v2.7): chart overlays depend on the visible window

**Where:** `components/price-chart.tsx:101–118` (BB from `closes` of the slice; VWAP accumulated from the first visible bar). Compare with the EMA/SMA at `121–128` (full history, then sliced) and MACD at `159` (full history). The engine's VWAP is session-anchored (`lib/indicators.ts:872–915`).

**Failures:**
- **Bollinger:** the first 19 visible bars have no band even when 10,000 bars of history exist. At 60-bar depth, a third of the chart has no band.
- **VWAP:** the value at a given bar changes with depth (60, 250, 1K and All give four different lines for the same candle). In `ChartReplay` (`chart-replay.tsx:100`, `visible` = depth), once `count > visible` the window slides on every "Next bar", so *every past VWAP point moves*. A replay tool should never repaint.
- The line is labelled "VWAP", but it is not the VWAP the engine votes on (`VWAP (session)` / `VWAP (20-bar)`).
- With pinch-zoom, each zoom step would redraw these lines.

**Fix:** compute every overlay on the full `klines` array and then slice, as the EMAs already do. For VWAP, call the engine's session-anchored series (same `intervalMs` rule) or label it "VWAP (from first visible bar)". Pass `intervalMs` into `PriceChart` for that.

## 6. Important (for v2.7): chart cost at "All saved"  **[run]**

**Where:** `price-chart.tsx` overall. `MAX_STORED_BARS = 10_000` (`lib/history-store.ts:14`). `page.tsx:1739` passes `visible = klines.length` for "All saved".

Measured with `renderToString` on a scratch copy (a lower bound; the client also does DOM diffing):

| bars | SVG elements | ms/render | markup |
|---|---|---|---|
| 250 | 1,244 | 31 | 154 KB |
| 1,000 | 4,994 | 62 | 576 KB |
| 10,000 | 49,994 | 355 | 5.6 MB |

`hoverIdx` is component state, so **every pointer move re-renders all candles, volume and MACD rects** and rebuilds the polyline strings. At 10k bars, `step = 688/10000 ≈ 0.07 px` while `bodyW` is clamped to 1.5 px, so candles overdraw about 20× anyway.

`Math.max(...spread)` is not a crash risk at this size. V8 handled 100k arguments and threw `RangeError` at 150k (measured), so the 10k store cap keeps it safe. It would become fragile only if the cap is raised.

**Fix:**
- Split static layers (candles, volume, MACD, overlays) into a `React.memo` child keyed on the model, and draw the crosshair and readout in a separate light layer.
- Decimate to at most about 1–2 candles per horizontal pixel (aggregate OHLC per pixel bucket) before rendering.
- For v2.7 full-screen/pinch, consider `<canvas>` for candles with SVG only for axes.
- Throttle pointer moves with `requestAnimationFrame`.

## 7. Important: release checks do not generalise to a second host; the doc claim is wrong

**Where:**
- `tools/release-check.mjs:119`: R8's `ALLOW` is a hard-coded `Set`.
- `docs/superpowers/specs/2026-11-07-v2.6-architecture-design.md:177–178` says *"in v2.6 it reads the same `public-hosts.ts` table, so R8 and R16 cannot disagree"*. The code does not do that. ADR-0003 line 47 ("R8 still polices `connect-src`") matches the code, so the plan is the inaccurate document.
- `tools/checks/public-hosts.mjs:29–34`: `parseTable` regexes only `COINSPH_ORIGIN`, `COINSPH_PROXY_PREFIX`, `COINSPH_READ_PATHS`.
- `src/lib/public-hosts.ts:86–88`: the runtime table `NATIVE_HOSTS` is generic.

**Failure:** v2.7 needs FX reference rates. If the chosen FX host sends no CORS header and is added the Coins.ph way (a second `NATIVE_HOSTS` entry plus a `/x/fx/*` rewrite):
- `isAllowedNativeUrl` allows it at runtime.
- R16 never checks it (it only reads the COINSPH constants and only flags rewrites that mention *Coins.ph's* host).
- R20 only polices `/openapi/` paths.
- R16's Tauri-scope check (`public-hosts.mjs:89–90`) compares the whole `http:` scope against Coins.ph URLs only, so adding the FX URL to `capabilities/main.json` makes R16 **fail**, with no supported way to make it pass.

R8 also never checks that desktop `connect-src` equals the web `CONNECT_SRC`. A host added to only one of them passes, and the other shell is then silently blocked.

**Fix:**
- Export one data table (e.g. `HOSTS = [{origin, via: "csp" | "native", paths, purpose, adr}]`) from `public-hosts.ts`.
- Generate `CONNECT_SRC` from its `csp` entries.
- Have R8, R16 and R20 parse or evaluate that table (or a JSON twin) and iterate every host.
- Add "desktop connect-src minus `ipc:` and `http://ipc.localhost` == web connect-src".
- Correct the plan text, or implement it.

## 10. Minor: preference normalisation drops entries and fields  **[run]**

**Where:** `lib/preferences-store.ts:80–87, 90–104`. Compare `market-client.ts:484` (accepts separators) and `page.tsx:243–248` (keeps them).

**Failure:** the user types `BTC-USDT, ETH/USDT`. This works in the session because `normalizeAssets` strips `-USDT` and `/USDT`. On reload, `normalizeMonitorAssets` strips only `USDT$`, which leaves `BTC-` and `ETH/`. Those fail `^[A-Z0-9]{1,15}$` and are silently dropped.
Verified: `["BTC-USDT","ETH/USDT","BTCUSDC","BTCFDUSD","XRP"]` becomes `["BTCUSDC","BTCFDUSD","XRP"]`.

`normalizePreferences` also returns a fixed shape: `displayCurrency` or `quoteByExchange` would be stripped on every load (verified) unless they are added there, to `AppPreferences`/defaults, and to the save effect's object and dependency list at `page.tsx:612–627`.

**Fix:** normalise monitor input once, in `parseAssetInput`, with the same `splitPair` logic. Add the v2.7 fields with allow-lists (ISO 4217 codes; per-venue quote sets).

## 11. Minor: R6 wildcard detection has holes  **[run]**

**Where:** `tools/release-check.mjs:106`, `/(^|\s)\*(\s|$)|https:\s|http:\s/` over `cspText`, which is joined with `"; "`.

**Failure:** `img-src *;` → no match. `img-src 'self' https:; …` → no match. `connect-src https://*.binance.com` → no match. Only `connect-src` is backstopped by R8. `img-src`, `script-src` and `font-src` wildcards would pass.

**Fix:** split each directive on whitespace and reject tokens equal to `*`, `https:`, `http:`, `data:` (outside img/font), or containing `*`.

## 12. Minor: service worker rules relevant to an FX source

**Where:** `apps/confluence/web/public/sw.js:64, 72–90, 111–127`.

- `url.hostname !== self.location.hostname` compares hostname, not origin. When the PWA runs from the local launcher on `127.0.0.1:<port>`, requests to the loopback gateway `127.0.0.1:8787` are intercepted and pass through the SWR handler. They are not cached only because `res.type` is `"cors"`. Use `url.origin !== self.location.origin`.
- The cache-first asset branch stores responses without checking `res.ok`, so a 404/500 for `/icon…` or `*.woff2` is pinned until the next `CACHE_VERSION`.
- **FX:** a cross-origin FX host is not intercepted (good), and a rewrite under `/x/` is network-only (good). Any other same-origin path (e.g. `/fx/latest.json` or `/rates?...`) would fall into stale-while-revalidate: the first paint uses yesterday's rate, and query-string variants accumulate in the cache. Put an FX rewrite under `/x/`. Persist the last good rate with its timestamp in the StoragePort for offline use, rather than relying on the SW.

## 13. Minor: i18n parity is enforced; two gaps matter for v2.7  **[run]**

How strings are added: keys go into `src/rsl/i18n/en.json` plus the 17 other catalogs. They are imported statically in `catalogs.ts:1–27`, where `null` becomes `""`. `scripts/validate-catalogs.mjs` (run by `pnpm test` → R10) enforces:
- exact key parity with English (`:61–64`)
- the same ICU argument names
- CLDR plural categories
- protected tokens (`BTC`, `ETH`, `Coins.ph`, `USDT`, …, `:51`)
- status and certification rules (`catalog-status.mjs`)
- safety-statement hashes (`tools/i18n-safety-lock.json`)

Gaps:
- **New ICU arguments must be added to `VARS`** (`validate-catalogs.mjs:48–50`). The kit leaves unknown arguments in place (`"Price in {currency}: 3"`, verified), so adding `{currency}` to `en.json` makes all 18 catalogs fail with "unrendered placeholder" until `VARS` gains `currency`.
- **Empty strings pass.** The kit returns `""` for an empty translation without calling `onMissing` (verified), and the validator does not flag it. A placeholder `""` or `null` in a draft catalog would ship blank labels.
- There is no check that keys used in code exist in `en.json`. Today all 306 `t("…")` keys exist (checked); a typo would show `⟦key⟧` at runtime.
- Much of the detail sheet and chart text is hard-coded English (`page.tsx:1696–1743`, `price-chart.tsx:243–467`). The v2.7 full-screen, zoom and currency strings should go through `t()`.
- `USDT` is a protected token, so en strings containing it (`paper.set.startingEquity`, `ph.localMarket`, `ph.premiumHelp`) must keep it in all 18 catalogs. Rewording them for multi-quote means touching every catalog.

## 14. Minor: Capacitor native GET redirects and abort  **[unverified default]**

**Where:** `packages/adapters/capacitor/index.js:23–27` (`CapacitorHttp.get` with no `disableRedirects`, no signal). Compare `packages/adapters/tauri/index.js:24–25` (`maxRedirections: 0`, signal passed).

**Risk:** if CapacitorHttp follows redirects by default (Android HttpURLConnection does for same-protocol redirects), a 3xx from an allow-listed path would be followed to a path or host the allowlist never saw. Superseded scans also cannot cancel in-flight native requests.

**Fix:** pass `disableRedirects: true` and treat 3xx as an error, mirroring Tauri. Any v2.7 FX native host inherits this.

## 15. Minor: a backfill loses all fetched pages on a mid-run rate limit

**Where:** `lib/market-client.ts:1160–1170`. `historyPage` throws `RateLimitError` from `fetchJson`; the loop does not catch it, so the bars already collected in `all` are dropped.

**Failure:** a Bitget 5,000-bar backfill (25 pages of 200) that hits a 429 on page 20 returns nothing, and the user must wait out the cooldown and refetch all 20 pages.

**Fix:** catch `RateLimitError` inside the loop, return what was collected with `complete: false`, and carry the retry-after to the caller.

## 16. Minor: chart accessibility and touch (prerequisites for pinch-zoom)

**Where:** `price-chart.tsx:291–311, 457`.

- `role="img"` on an element with `tabIndex=0` and key handling. Use `role="application"` (or `group`) with an `aria-roledescription`, and expose the readout via `aria-describedby`.
- The `aria-live="polite"` readout updates on every pointer move, which floods screen readers. Announce only on keyboard moves, or debounce.
- There is no `touch-action` on the SVG. On phones a horizontal drag starts a pan of the dialog, the browser fires `pointercancel` after one or two moves, and scrubbing works only by tapping.
- **For v2.7 pinch/pan:**
  - set `touch-action: none` (or `pan-y` with your own horizontal handling) on the plot only;
  - use `setPointerCapture`;
  - track two pointers for pinch;
  - handle `pointercancel`.
- **Android back:** it dispatches `Escape` to close the top dialog (`rsl/RslContext.tsx` `onBack`). A CSS "pseudo-fullscreen" overlay inside the Radix Dialog would be closed together with the dialog by Esc or back. Give full-screen its own Escape/back handling that runs first.
- **Desktop:** if full-screen uses the Tauri window API, the capability `core:window:allow-set-fullscreen` is absent from `capabilities/main.json` **[unverified which API v2.7 will use]**.
