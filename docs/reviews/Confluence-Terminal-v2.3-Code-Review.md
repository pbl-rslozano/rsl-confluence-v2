### Summary
The v2.3 safety boundaries hold. No order path exists, the MCP server is read-only and makes no network calls, the Telegram token is redacted everywhere, the CSP is unchanged and dependencies are pinned. The block bootstrap, the block-return PSR/DSR and the CSCV PBO are now statistically sound. The research layer still has defects that bias the go/no-go evidence:
- Signals are charged different costs than their benchmarks, which manufactures about 10 bp of "edge" from noise.
- The label-shuffle test rejects a true null about 35 % of the time.
- Pre-registration and the trials count are not enforced the way the UI claims.
- Catch-up rows carry selection look-ahead.

There are also cursor, storage-growth and performance problems that appear at realistic ledger sizes.

### What Looks Good
- **No order path anywhere.** The paper broker and risk engine are pure and take no network, keys or clock. The gateway only checks API-key permissions. No file in scope imports `private-api` or a fetch function into the paper or MCP code.
- **MCP server.** It is read-only, the network globals are replaced with throwing stubs, and the only write is an append to `trials.jsonl` with `O_APPEND|O_NOFOLLOW`. Path guards reject `..`, absolute paths, drive letters and NUL, and check the realpath of symlinks. Reads are size-, depth- and count-limited, and every response carries the disclaimer.
- **Recorder.** The runtime egress guard enforces https, the host allowlist and `redirect: "error"`, and is installed as the global `fetch`. The bot token and webhook URL are redacted from every log, heartbeat and error path, and are never persisted (the outbox stores text and fields only). Alerts are marked before sending, writes are atomic, torn tails are repaired and a single-instance lock prevents double runs. A failed catch-up correctly leaves the recorder cursor unchanged, unlike the app.
- **Statistics fixed since v2.2 and verified calibrated.** The block bootstrap (`bootstrapMean` with block keys) and PSR/DSR on block returns hold their nominal rates under a clustered null (2/60, 6/120). `pbo()` implements CSCV correctly: its rank+0.5/N logit is equivalent to the paper's r/(N+1), it uses the Sharpe metric and C(8,4) = 70 splits. The Wilson interval formula is correct.
- **No look-ahead found** in `enrich` (beta, HTF and taker delta use bars ≤ t; catch-up slices `kl` to `i+1`), the momentum sign (close t vs t−20), snapshots (measured from closed bars, never overwritten), or BTC excess (same next-open → t+h window in the app, replay and MCP).
- **Shared row assembly.** `scan-record.ts` is shared by the app and the recorder, the bar docs are documented and a universe log exists. Turnover-floor and universe ordering are correct, and the Binance taker-buy field (index 9) is right.
- **Untrusted input.** `sanitizeLedgerRow` binds `id` to cfg|src|tf|pair|t and whitelists fields. The ZIP reader is zip-slip-safe (fixed output name), checks the declared size and requires a matching SHA-256 CHECKSUM.
- **i18n and tooling.** Every key referenced by the new UI exists in all 18 catalogs with consistent ICU arguments. Dependencies are pinned exactly, only `packages/adapters` imports Tauri/Capacitor, the CSP `connect-src` is unchanged, and check-egress / R11 pass.
