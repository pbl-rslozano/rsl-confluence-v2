# v2.8 Step 1 — Safety fixes, licence credits, smooth loading — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship WP19 (safety and honesty fixes), WP20 (licence credits and source terms) and WP27 (smooth loading) as one pull request with every check green.

**Architecture:** Paper-risk rules stay pure functions in `risk-engine.ts` / `paper-broker.ts`; the book moves to `PAPER_SCHEMA` 2 with a migration in `paper-store.ts`. Engine changes (Pattern, FVG) bump `ENGINE_VERSION` to 2.4.0 with a re-pinned config id. Smooth loading adds a per-series callback to the direct-fetch path and a delta request size computed from on-device history; the scan scores rows as they arrive and computes cross-sectional fields once the list is complete.

**Tech Stack:** TypeScript (Next.js static export), Node test runner via `scripts/run-engine-tests.mjs` and `node --experimental-strip-types --test`, Node gateway (`.mjs`), Playwright acceptance (`tools/e2e/acceptance.cjs`).

**Spec:** `docs/superpowers/specs/2026-11-15-v2.8-architecture-design.md` (revision 12, commit 32c2612) — §0, §3, WP19, WP20, WP27, §4.

## Global Constraints

- Design-unchanged rule (§3): DS-1/DS-2 bounding boxes within ±2 px, text masked, clock frozen (`page.clock`), FX mocked. New UI only in places §3 items 1–8 allow (More statistics, settings rows, About collapsed section, banner text).

- All new UI strings go through i18n (`en.json` source; tier-2 catalogs fall back to English, status stays DRAFT).
- Exact pinned versions; no new runtime dependency.
- `ENGINE_VERSION` "2.4.0"; 2.3.0 ledger rows stay and are reported separately.
- Docs parity (R19): plan has `<!-- user-visible: ... -->` and `### WPn` headings; guide has `<!-- wp:WP19 -->`, `<!-- wp:WP20 -->`, `<!-- wp:WP27 -->`; CHANGELOG top entry `# v2.8.0` names the WPs.

## Review Focus

1. **A v1 paper book with open positions is opened by v2.8** → migrates to schema 2 with `peakEquity` = current marked equity (never a lock on first open); nothing lost. (Task 1 test `migrates v1 book with open positions`.)
2. **App closed for days, drawdown breached meanwhile** → on the next scan positions of the scanned series close at that series' next open with reason "drawdown lock"; other series close at their own next scan; RESET stays disabled and names the series still to scan. (Task 1 test `lock closes unscanned series later and RESET waits`.)
3. **Stored history has a gap, or the exchange revised the overlap bar** → delta fetch is abandoned for that series and the full 1,000-bar window is fetched; scores equal a full fetch. (Task 12 test `delta overlap mismatch falls back to full window`.)
4. **User switches source or timeframe mid progressive scan** → queued work cancels; no row of the old source/timeframe appears in the new list. (Task 12 test `switching source cancels and never mixes rows`.)
5. **A v2.7 ledger CSV (no `vt`, `pd`, `pc`, `fr`, `oiChg`) or a hostile CSV is imported** → old rows import with the new fields null; out-of-range or formula-like values are rejected by the sanitiser. (Task 7 test `v2.7 CSV imports with null new fields; hostile values rejected`.)
