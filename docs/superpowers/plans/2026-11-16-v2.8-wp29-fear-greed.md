# v2.8 WP29 — Fear & Greed widget (GCMDSI port) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put the GCMDSI Fear & Greed gauge and its 31-day history on the main screen, directly below the counts line (ASSETS · BULL · BEAR · NEUTRAL · REV). The widget is collapsed by default, so the layout at rest is unchanged.

**Architecture:**
- **Toggle chip.** A small chip at the end of the header's counts line opens and closes a panel just below that line. The chip is a new spec §3 item-8 owner-approved addition, excluded from DS-1 by its `data-testid`.
- **Data module.** `lib/fear-greed.ts` fetches `https://api.alternative.me/fng/?limit=31&format=json` only while the panel is open. It validates every row and caches the result for 1 h in the "meta" store.
- **Drawing.** `components/fear-greed.tsx` draws the gauge and the history as React SVG. They are ported from the GCMDSI v1.0 kit (`src/core.mjs` `sentimentLabel`/`sentimentColor`/`parseFearGreed`, `src/app.mjs` `gaugeSvg`/`historySvg`), rewritten as JSX with no `innerHTML`.

**Tech Stack:** Next.js 15 / React (static export), TypeScript tests through `scripts/run-engine-tests.mjs`, Playwright 1.63 acceptance.

**Spec:** `docs/superpowers/specs/2026-11-15-v2.8-architecture-design.md`. Task 1 adds this as **WP29** (owner decision of 16 Nov 2026, recorded in §0). Owner decisions:
- placement: main screen, below the counts line;
- contents: the Fear & Greed gauge and history only. The session clock, regional CSV, experimental composite and CoinGecko prices are left out;
- default: collapsed;
- order: after Step 4b, which is merged as PR #9.

## Global Constraints

- **Context, never a vote.** The index never reaches scoring, the ledger, alerts or paper-trading rules.
- **Fetch gate.** `api.alternative.me` is contacted only while the panel is open: on open, then at most once per hour while it stays open.
  - At rest, with the panel collapsed (the default), no request is made.
  - If the user leaves it open, the open state is remembered per device, so the next load fetches. That is the user's choice.
- **Endpoint, verbatim:** `https://api.alternative.me/fng/?limit=31&format=json`.
  - Response: `{ name, data: [{ value: "<int string>", value_classification, timestamp: "<unix s string>", time_until_update? }], metadata: { error } }`.
  - Order is newest first. `time_until_update` appears on the newest row only.
  - CORS from the app origin was confirmed on 16 Nov 2026: HTTP 200 with 31 rows from `https://effervescent-bubblegum-1e5c03.netlify.app`.
- **Attribution (Alternative.me terms, verbatim).**
  - "You must properly acknowledge the source of the data and prominently reference it accordingly."
  - "Commercial use is allowed as long as the attribution is given right next to the display of the data."
  - The data must not be used to impersonate Alternative.me.
  - So the panel shows, next to the gauge: "Data: Alternative.me Crypto Fear & Greed Index", linked to `https://alternative.me/crypto/fear-and-greed-index/`. The same source is listed in About → Data sources & thanks.
- **Bands** (labels the app draws itself when the API's classification is missing; ported from the kit):
  - 0–24 Extreme Fear `#fd5b70`
  - 25–44 Fear `#f59b6b`
  - 45–55 Neutral `#eccb77`
  - 56–75 Greed `#79d59e`
  - 76–100 Extreme Greed `#28cdb0`

  Show the API's own `value_classification` text when it is one of the five known labels, otherwise the app's band label. The gauge arc colours follow the bands, and must meet contrast on both themes; adjust lightness for the light theme if needed and say so.
- **New host, all touchpoints:**
  - `https://api.alternative.me` goes in `CSP_HOSTS` (`public-hosts.ts`), the tauri connect-src, the egress manifest `web.csp`/`web.hosts`, and an ADR-0003 amendment that quotes the probe and the terms. R8 must pass.
  - Probe evidence goes in `docs/research/evidence/wp29-fng-probe-2026-11-16.json`.
  - The recorder, gateway and MCP never call it.
- **No new dependency.** No `innerHTML` and no `dangerouslySetInnerHTML`. Every provider string is rendered as text.
- **i18n.** New strings go into all 18 catalogs, with the Arabic drafts in `@pendingReview` and new ICU variables in VARS. Right-to-left: the history reads oldest → newest in reading order, so it is mirrored in RTL like the radar spark. The gauge is not mirrored: 0 is on the left in every language, as on Alternative.me.

## Review Focus

1. **A collapsed widget makes a request.** Possible triggers: React strict-mode double effects, the remembered state read late, or a prefetch on hover. Expect zero requests to `api.alternative.me` at rest.
2. **Hostile or odd API rows.** Watch for `value` "101", "-1", "12.5" or "abc"; `timestamp` "0" or far in the future; duplicate days; `metadata.error` set; an empty `data`; and a classification string with markup. Invalid rows are dropped. With fewer than 2 valid rows, no history is drawn. With none, the panel says unavailable. Nothing throws.
3. **The open panel pushes the coin list down** and must not overlap it. Collapsing returns the exact at-rest layout. Phone width (390 px) keeps working.
4. **The cached value is shown as current after a long gap.** The panel always shows the observation date. A cache older than 1 h is refetched on open; if the refetch fails, the cached value is shown with "last value {date}".
5. **Keyboard and screen readers.** The chip is a button with `aria-expanded` and `aria-controls`. The panel has a heading. The gauge has a text alternative ("Fear & Greed 10, Extreme Fear, 16 Nov 2026"), and the history has a summary.

**Interfaces:**
- Produces:
  - `FNG_URL = "https://api.alternative.me/fng/?limit=31&format=json"` (written literally).
  - `type FngBand = "extremeFear" | "fear" | "neutral" | "greed" | "extremeGreed"`.
  - `interface FngPoint { t: number; value: number; label: string; band: FngBand }`, where `t` is in ms at 00:00 UTC.
  - `interface FngData { asOf: number; points: FngPoint[] }`. `points` are oldest first, deduped by UTC day (last wins), at most 31.
  - `fngBand(v: number): FngBand` (bands above). `FNG_COLORS: Record<FngBand, string>`.
  - `parseFng(json: unknown, now: number): FngData | null`. Rules:
    - `value` must be a string or number giving an integer 0..100.
    - `timestamp` is unix seconds, > 2018-01-01 and ≤ now + 1 day.
    - `label` is the API text if it is one of "Extreme Fear", "Fear", "Neutral", "Greed" or "Extreme Greed"; otherwise the English band name.
    - It returns null when `metadata.error` is a non-empty string or no row is valid. It never throws.
  - `fetchFng(signal?: AbortSignal, fetcher = fetch): Promise<FngData>`. It uses `cache: "no-store"` and a 10 s timeout combined with the caller's signal. Use `AbortSignal.any` only when present; otherwise fall back to a controller, as `lib/provider-data-client.ts` does. Any failure, including null from `parseFng`, rejects with `Error("fng:unavailable")`.
  - Cache in the "meta" store: `FNG_CACHE_ID = "fng-cache"`, `FNG_TTL_MS = 3_600_000`, with:
    - `loadFngCache(port, now): Promise<FngData | null>`, which re-runs the parse checks on stored points;
    - `saveFngCache(port, data): Promise<void>`;
    - `isFngFresh(data, now): boolean`, meaning `now − asOf < FNG_TTL_MS`.

    Use the `RadarPort` shape from `lib/radar/store.ts` (`get`/`put`) as the port type.
