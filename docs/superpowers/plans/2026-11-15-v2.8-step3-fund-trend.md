# v2.8 Step 3 — Fund trend (WP21) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the Fund trend benchmark: a value from −100 to +100 based on time-series momentum, computed from closed daily bars, plus a Fund size figure. It appears in an opt-in chart ribbon and an opt-in panel; disagreements with the Confluence score are marked and can pulse; there is an optional Fund rank; and every ledger row records `ft` as a benchmark. Nothing changes by default.

**Architecture:**
- `lib/fund-trend.ts` holds the pure maths: no I/O, testable in Node.
- `lib/fund-trend-feed.ts` loads closed daily bars per pair. It goes through the existing history store and the WP27 delta fetch, uses each venue's rate gate, and runs behind the scan.
- The chart draws the ribbon, panel and disagreement marks from these values.
- The panel's per-bar Confluence line reuses the worker's catch-up scoring (`runCatchUp` in `lib/scan-jobs.ts`) with full 1,000-bar windows.
- The ledger stores `ft`, and the report adds a "Fund trend sign" benchmark next to the existing 20-bar momentum one.

**Tech Stack:** Next.js static export, TypeScript, custom canvas/SVG chart (`components/price-chart.tsx`), Node test scripts, Playwright acceptance.

**Spec:** `docs/superpowers/specs/2026-11-15-v2.8-architecture-design.md` (rev 12): WP21, §0 owner decisions (14–15 Nov), §3 design-unchanged rule.

## Global Constraints

- **Method (verbatim intent):**
  - Use closed daily bars and log returns over k = 30, 91 and 365 days.
  - Daily σ is the EWMA of squared daily log returns, not demeaned, with centre of mass 60 (δ = 60/61), using returns up to t−1. Annualised σ = σ·√365.
  - zₖ = ln(Cₜ / Cₜ₋ₖ) / (σ·√k), clipped to ±2. **Fund trend** = 50 × mean(zₖ), giving −100…+100.
  - **Fund size** = min(200 %, 40 % ÷ annualised σ).
  - At least **366** closed daily bars are needed; otherwise show "not enough history".
- **Rows:** crypto rows only (spot, perps and Coins.ph peso pairs, each from its own daily bars). Tokenised stocks, FX and commodities show "n/a". The value does not depend on the row's timeframe.
- **No look-ahead:** a bar's value uses only daily bars whose **close time ≤ that bar's close time**. For intraday bars this means daily bars closed before the bar's day.
- **Budget:**
  - At most one daily request per crypto pair per UTC day, at limit 1,000, from the row's own source and hosts.
  - It is cached per UTC day per pair, queued **behind** the scan with the existing pacing, venue rate gates and 429/418 halt.
  - No new hosts.
- **On screen, all off by default** (§3 item 2: opt-in Indicators toggles, never added to `LAYERS`; item 3: settings default off):
  - **Ribbon:** green up, red down, grey when |x| < 15; opacity rises with |x|.
  - **Panel:** Confluence score and Fund trend share one −100…+100 axis; Fund size is a shaded area.
  - **Disagreement:** Confluence |score| ≥ 55 against a Fund trend of the opposite sign with |x| ≥ 25. It shows as diagonal hatching on those bars plus a ◆ marker. The list row gets ◆ and a thin outline **only when the ribbon is on**.
  - **Pulse:**
    - default: new disagreements pulse 3× over about 3 s, then stay;
    - Off;
    - Keep pulsing: at most 1 pulse/s until the coin is opened, with a stop button.
    - `prefers-reduced-motion` means no animation.
  - **Fund rank:** the rank of the coin's Fund trend across the scanned crypto rows. It shows in the panel. An optional list column is off by default, and Scenarios uses it later (WP22).
- **Per-bar panel score:**
  - Score only the visible bars (≤ 300) whose full 1,000-bar window (the bar plus 999 closed bars before it) is available.
  - Re-score them in the scan worker on the `runCatchUp` path with the production window, cached per pair, timeframe and last bar.
  - Reuse ledger rows where they exist (same `cfg`, `wb` = 1,000).
  - 300 scored bars need ≥ 1,299 contiguous bars. With fewer, fetch the missing older bars **once** (same host, one history page). Otherwise draw the line only where a full window exists, and say so.
  - Scored bars use exactly the list's score. Other bars show no line.
- **Ledger:** `ft` is recorded per row, nullable, as a benchmark and never scored. The report adds "Fund trend sign" next to the 20-bar momentum.
- **Unchanged:** engine config id `5c30b5c39f5ba3f2` and `ENGINE_VERSION` 2.4.0 (Fund trend is not a vote). DS-1/DS-2 stay green.
- **Repo rules (CLAUDE.md):**
  - Never delete an acceptance check.
  - `packages/core` untouched.
  - No organisation or contact details.
  - Tier-2 catalogs never CERTIFIED. New keys go into all 18 catalogs; Arabic drafts are listed in `@pendingReview` (R25); ICU vars go into VARS in `scripts/validate-catalogs.mjs`.

## Review Focus

1. **A young coin (365 daily bars), or one missing days in its daily series.**
   - Show "not enough history", never a number.
   - A daily gap ends the usable run (`contiguousTail` on daily bars).
   - Test: Task 1, `needs 366 contiguous closed daily bars`.
2. **The open daily bar, or a scan just after 00:00 UTC.** Today's forming daily bar is never used. The value refreshes once the new daily bar closes. Test: Task 1, `ignores the open daily bar`; Task 2, `cache refreshes after the UTC day changes`.
3. **No look-ahead on intraday history:**
   - A 4h bar at 10:00 on day D uses daily bars closed at or before its close (D−1's bar closes at D 00:00).
   - The ledger catch-up and the panel follow the same rule.
   - Test: Task 1, `intraday bar uses only daily bars closed before its close`.
4. **A rate limit while daily bars load behind a scan.** The loading stops for that venue and the cooldown is honoured. Rows already loaded keep their value; the others show "…". The next scan is not blocked beyond the venue cooldown. Test: Task 2, `429 halts daily loading without touching scan rows`.
5. **The ribbon off while a disagreement exists.**
   - The list shows no ◆ or outline.
   - Turning the ribbon on shows them.
   - Turning it on does not replay pulses already shown for the same disagreement (one pulse per new disagreement per pair and bar).
   - Test: Task 6, `list marker only with ribbon on; pulses once per new disagreement`.

### Task 1: Fund trend maths

**Files:**
- Create: `apps/confluence/web/src/lib/fund-trend.ts`, `fund-trend.test.mjs` (script `test:fundtrend`, added to the `test` chain)

**Interfaces:**
- Produces:
  - `FT_HORIZONS = [30, 91, 365]`, `FT_DELTA = 60/61`, `FT_CLIP = 2`, `FT_SCALE = 50`, `FT_TARGET_VOL = 0.40`, `FT_SIZE_CAP = 2`, `FT_MIN_BARS = 366`, `FT_GREY = 15`, `FT_DISAGREE_SCORE = 55`, `FT_DISAGREE_FT = 25`
  - `interface FundTrend { value: number; size: number; z: [number, number, number]; sigmaAnn: number; asOf: number /* close time (ms) of the last daily bar used */ }`
  - `type FundTrendState = FundTrend | { na: "history" | "class" | "loading" | "error" }`
  - `fundTrend(daily: Kline[], asOfClose: number): FundTrend | null`
    - Uses only daily bars with close time ≤ `asOfClose`, after `contiguousTail`.
    - Returns null when fewer than 366 bars remain.
  - `fundTrendSeries(daily: Kline[], bars: { time: number; closeTime: number }[]): (number | null)[]`
    - Gives each bar's value from daily bars with close ≤ that bar's close time.
    - Memoised by the last daily bar used, so 300 bars cost at most about 2 distinct computations per day.
  - `isFundTrendClass(ac: AssetClass): boolean` (crypto only)
  - `fundRank(values: Map<string, number>): Map<string, number>` (1 = strongest positive; ties share a rank; n/a excluded)
  - `disagreement(score: number, ft: number | null): -1 | 0 | 1`
    - `1` when score ≥ 55 and ft ≤ −25; `-1` when score ≤ −55 and ft ≥ 25; else 0.
  - `ribbonStyle(x: number | null): { colour: "up" | "down" | "grey" | "none"; alpha: number }`
    - "grey" when |x| < 15.
    - alpha = 0.25 + 0.75·min(1, |x|/100).
- EWMA seed: σ² starts as the mean of the first 60 squared daily log returns, then σ²ₜ = δ·σ²ₜ₋₁ + (1−δ)·r²ₜ₋₁ (returns up to t−1).
- Floor: σ is floored at 1e-8; z is 0 when the log return is 0.

- [ ] **Step 1: Write the failing tests** (daily bars at 00:00 UTC; close = open + 86,400,000):
  - **`constant +1 % daily returns saturate`:** 400 bars with ln-return 0.01 give value 100, z = [2, 2, 2], sigmaAnn ≈ 0.01·√365 (±1e-9), size 200.
  - **`constant −0.5 % daily returns`:** value −100, size 200 (0.40/0.0955 > 2).
  - **`flat prices give 0`:** value 0, size 200.
  - **`unsaturated case matches a reference`:** returns alternating `d ± a` (d = 0.0005, a = 0.03, 420 bars). The value equals an independent reference written in the test from the spec formulas, within 1e-9, and |value| < 100.
  - **`size below the cap`:** with σann > 0.20 (e.g. a = 0.05), size = 0.40/σann × 100.
  - **`needs 366 contiguous closed daily bars`:** 365 bars return null; 366 bars return a value; a missing day 10 bars back leaves only the tail and returns null.
  - **`ignores the open daily bar`:** a bar with close > `asOfClose` changes nothing.
  - **`intraday bar uses only daily bars closed before its close`:** a 4h bar on day D from 08:00 to 12:00 gets the same value as `fundTrend(daily, D 00:00)`. A 1d bar D gets `fundTrend(daily, D+1 00:00)`.
  - **`disagreement thresholds`:**
    - (55, −25) → 1; (54, −25) → 0; (55, −24) → 0; (−60, 30) → −1.
    - With ft null → 0.
  - **`ribbonStyle`:**
    - null → none; 10 → grey; 15 → up with alpha 0.3625; −100 → down with alpha 1.
  - **`fundRank`:** {A: 50, B: −10, C: 50} → A = 1, C = 1, B = 3.
  - **`isFundTrendClass`:** crypto true; stock, fx and commodity false.
