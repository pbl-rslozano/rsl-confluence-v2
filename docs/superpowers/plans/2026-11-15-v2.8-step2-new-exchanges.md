# v2.8 Step 2 — New exchanges (OKX, Coinbase, Upbit) and "Data sources & thanks" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add OKX spot and perpetual, Coinbase spot and Upbit spot as keyless scan sources on the existing pipeline. Add a "View on [exchange]" link at the end of the detail sheet and a "Data sources & thanks" section in About.

**Architecture:**
- Each venue gets its own module (`okx.ts`, `coinbase.ts`, `upbit.ts`) for interval mapping, paged candles, ticker parsing and id normalisation. `market-client.ts` only dispatches to them.
- OKX and Coinbase allow cross-origin requests, so they are direct-fetch CSP hosts.
- Upbit's CORS is unreliable, so it follows the Coins.ph pattern: same-origin rewrite on the web, path-scoped native allowlist, and plain fetch in Node. A small generic relay (`native-relay.ts`) carries it, and Coins.ph is left unchanged.

**Tech Stack:** Next.js static export, TypeScript, Node test scripts (`scripts/run-engine-tests.mjs`), Playwright acceptance (`tools/e2e/acceptance.cjs`). No new dependency.

**Spec:** `docs/superpowers/specs/2026-11-15-v2.8-architecture-design.md` (rev 12) — WP26, §3 design-unchanged rule, §4, §6.

**Build-time evidence (binding numbers):** `docs/research/evidence/wp26-venues-probe-2026-11-15.json`. This is a browser probe from the owner's computer covering CORS, limits, row layouts, open-bar flags and timeframe support. Implementers cannot reach the venues from the build container (proxy 403). Use this file and its samples as fixtures, and never guess a field.

## Global Constraints

- Closed bars only; pacing; global 429/418 halt across tiers (WP27 `runTiers` / `RateLimitError`); quote handling from WP12 (`pickQuotes`, `splitPair`, `rememberPairs`).
- Pair ids normalise to `[A-Z0-9]{2,30}`. `BTC-USD` (Coinbase) becomes `BTCUSD`, `KRW-BTC` (Upbit) becomes `BTCKRW`, and `BTC-USDT-SWAP` (OKX) becomes `BTCUSDT` under the source `okx-perp`.
- New source ids, used verbatim everywhere: `okx`, `okx-perp`, `coinbase`, `upbit`. Labels are "OKX Spot", "OKX Perpetual", "Coinbase (US)" and "Upbit (KR)".
- Keyless: no `privateApi` on any new source (R20), no account endpoint, no order endpoint, no referral codes, no embedded exchange.
- Non-USD quotes (KRW, BTC) use the venue's own USDT market for the scan's USD volume and the liquidity floor, never display FX rates (R21).
- Hosts: exactly `https://www.okx.com` and `https://api.exchange.coinbase.com` in `CSP_HOSTS`, and `https://api.upbit.com` in `NATIVE_HOSTS` (read paths only). Each needs an ADR-0003 amendment "v2.8 (WP26)" and R8/R16 green. No other host.
- Design-unchanged (§3): the only visible additions allowed are the new exchanges in the source menu, "View on [exchange]" at the end of the detail sheet (the top of the sheet keeps its v2.7 layout), and a **collapsed** "Data sources & thanks" section in About. DS-1/DS-2 must stay green.
- Engine unchanged: `ENGINE_VERSION` 2.4.0 and config id `5c30b5c39f5ba3f2`.
- i18n: new keys go into all 18 catalogs via `python3 /tmp/claude-0/-home-claude/d2c2c0f0-56a8-5561-b426-c68b21674b3e/scratchpad/tools/addkeys.py`. Arabic gets drafts listed in `@pendingReview` (R25); tier-2 catalogs get the English fallback and are never CERTIFIED. ICU placeholders go into VARS in `scripts/validate-catalogs.mjs`.
- Venue limits are recorded as constants in each venue module, with a comment citing the probe file or the docs URL. Anything not confirmed says "[not verified]".
- Never delete an acceptance check, never touch `packages/core`, and include no organisation details.

## Review Focus

1. **The newest bar is still open:**
   - OKX marks it with `confirm` = `"0"`.
   - Coinbase and Upbit give no flag; the newest row is the forming bar.

   It must never be scored, recorded or shown as closed. Tests: Tasks 3, 4 and 5, `drops the open bar`.
2. **Paged fetches that overlap, come back short, or hit gaps.** This covers Coinbase publishing no candle for an interval with no trades, and pairs listed less than 1,000 bars ago. The merged series must be sorted, de-duplicated and contiguous (`contiguousTail`), and anything below 1,000 bars must be scored cold (`wb` < `ENGINE_BARS`), never padded. Tests: Tasks 4 and 5, `pages merge without duplicates`; Task 4, `gap keeps newest contiguous run`.
3. **A 429 or 418 on page 3 of 5.** The series is not returned partially as if complete. `RateLimitError` propagates, the scan halts across tiers, and the venue's cooldown is set. Test: Task 3, `rate limit mid-paging halts the series`.
4. **The Upbit relay is unavailable.** Examples: a missing rewrite, or a native path that the allowlist refuses. Upbit then reports "feed unavailable" and other sources are unaffected. There is no fallback to a direct cross-origin fetch. Test: Task 2, `relay refuses a path outside the allowlist`; Task 5, `relay failure is a feed error, not a direct fetch`.
5. **KRW and BTC prices:**
   - KRW prices convert to the display currency through FX, like PHP.
   - BTC-quoted prices never pass through fiat FX, and the scan line says "prices in BTC".
   - The USD volume used for the liquidity floor comes from Upbit's own `KRW-USDT` and `USDT-BTC` markets.

   Tests: Task 1, `price currency per quote`; Task 5, `KRW volume uses KRW-USDT`.
