# v2.8 WP28 — Encrypted cloud backup (Google Drive, OneDrive, pCloud, Backblaze B2, Cloudflare R2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an optional, collapsed **Cloud backup (encrypted)** section to Settings (the About dialog, which the desktop
**Settings…** menu item opens). It encrypts the user's own records on the device with a passphrase (AES-256-GCM, key from
PBKDF2-SHA-256 at 600,000 iterations) and uploads one text file to Google Drive, OneDrive, pCloud (sign-in from the app,
PKCE or token flow, no client secret), or Backblaze B2 / Cloudflare R2 (bucket-restricted keys held by the local gateway).
Restore downloads, decrypts and validates the file, shows the backup time and what will change, and asks before replacing
newer settings.

**Architecture:**
- **Pure core** (flat files in `apps/confluence/web/src/lib/`, relative imports only so `run-engine-tests.mjs` can run them):
  - `backup-crypto.ts`: the encrypted envelope.
  - `backup-payload.ts`: what is backed up and how it is validated.
  - `backup-service.ts`: create, open and plan a restore, apply it, through injected stores.
  - `backup-providers.ts`, `backup-oauth.ts`, `backup-session.ts`, `backup-http.ts`: provider registry, sign-in, in-memory
    tokens and an injected HTTP port.
  - `backup-targets.ts`: Google Drive, OneDrive and pCloud storage calls.
  - `backup-gateway-client.ts`: B2 and R2 through the gateway.
- **Transport.**
  - Web: `fetch`, policed by the CSP (OneDrive and pCloud only; Google is "desktop app only" on the web).
  - Desktop and phone: native HTTP from `packages/adapters`, fenced by `isAllowedBackupUrl` and the Tauri HTTP scope.
  - The OAuth redirect is handled in the shells: a Rust loopback listener on `127.0.0.1:48787` (desktop) and an app link
    (phone, only when the owner has set it up).
- **Gateway.** B2 and R2 are provider profiles (`kind: "provider"`, the WP25 kind). SigV4 is written on `node:crypto`. The
  `/backup/*` routes have their own 20 MB body limit.
- **UI.** `components/cloud-backup.tsx` is mounted inside About only while its `<details>` is open. At rest nothing is
  computed and nothing is requested.

**Tech Stack:** Next.js 15 / React 19 static export, TypeScript run by `node --experimental-strip-types` (`scripts/run-engine-tests.mjs`), WebCrypto (`crypto.subtle`), `CompressionStream`/`DecompressionStream`, Node 22 gateway (`node:crypto`, `node:http`), Tauri 2 (Rust `std::net` only), Capacitor 8 (`@capacitor/app`, `CapacitorHttp`), Playwright acceptance (`tools/e2e/acceptance.cjs`).

**Spec:** `docs/superpowers/specs/2026-11-15-v2.8-architecture-design.md` rev 13: §WP28 (lines ~495–521), §WP25 "provider-profile kind" paragraph (~426–433), §3 item 8 (Backup in Settings, collapsed), §4 (BK-*, docs, ADR-0019), §6 (build-time host checks). Owner decisions of 17 Nov 2026 (below) override where they are more specific.

## Global Constraints

- **Owner decisions (17 Nov 2026), verbatim intent:**
  - All five providers are built.
  - OAuth client IDs come from build-time configuration and are empty by default. A provider without a client ID shows
    "Not set up yet" and is excluded from every network path.
  - Every provider flow is tested against mocks. No live sign-in is needed for any gate.
  - B2 and R2 go through the desktop gateway with the user's own bucket-restricted keys, held in memory. The upload route
    has its own ≤ 20 MB body limit.
  - Google on the web is "desktop only", and ADR-0019 records why.
  - The §6 CORS and terms checks for the new hosts are **documented manual checks** (owner notes), marked **deferred** in
    ADR-0019 and in the ADR-0003 amendment.
- **Crypto (verbatim):**
  - AES-256-GCM via WebCrypto, 96-bit IV, 128-bit tag.
  - Key from **PBKDF2-SHA-256 with 600,000 iterations**. Source: OWASP Password Storage Cheat Sheet, "PBKDF2-HMAC-SHA256:
    600,000 iterations", https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html, read
    17 Nov 2026. Cite it in ADR-0019.
  - Salt 16 random bytes. The passphrase is NFC-normalised UTF-8 and at least 12 characters.
  - The authenticated header (GCM additional data) carries schema version, cipher, KDF, iteration count, salt, compression,
    backup time and app version.
  - The passphrase is **never stored, logged, uploaded or put in an error or audit entry**.
- **Restore (verbatim):**
  - Plain `JSON.parse` only: no `eval`, `Function`, HTML or `innerHTML`.
  - Schema version, field types and sizes are validated. The file is ≤ **20 MB** (20 × 1024 × 1024 bytes). Inside the
    authenticated ciphertext the payload is gzip-compressed and capped at 160 MB once decompressed (see the conflict table).
  - Nothing is ever executed.
  - The backup time is shown, and the user is asked before newer settings are replaced. Records are merged by id and never
    overwritten.
  - An invalid, oversize, wrongly keyed or tampered file changes nothing.
- **What is backed up (the user's own records):**
  - Signal ledger rows.
  - Pre-registrations and registered trials (the multiple-testing count).
  - The paper **journal**.
  - App preferences (`preferences/current`).
  - The scoring profile (`preferences/scoring-profile-v1`).
  - **Not backed up:** market history, the paper account, open positions and risk settings (a restore must never loosen a
    drawdown lock), tokens, keys, the passphrase, radar caches. The existing `.rslbak` export is unchanged.
- **No new dependency** (npm or crate), exact pinned versions unchanged. WebCrypto, `CompressionStream`, `node:crypto`,
  `std::net`, and the already-installed `@tauri-apps/api`, `@tauri-apps/plugin-http`, `@tauri-apps/plugin-opener`,
  `@capacitor/app` and `@capacitor/core`.
- **Shell boundary:** only `packages/adapters` imports `@tauri-apps/*` or `@capacitor/*` (R5). `packages/core` is untouched (R4).
- **Tokens:** OAuth access tokens live in `backup-session.ts` memory only, are cleared on reload, and are never written

  - No refresh tokens: no `offline_access` scope.

## Review Focus

1. **Restoring onto a device that keeps less.**
   - Cases: the browser's localStorage fallback (14 days, 5,000 rows) or the memory store (2 days) receiving a year of
     SQLite rows.
   - Expected: rows older than the device keeps and rows the row cap removes are **counted and shown** before confirming
     and in the result. `added + duplicates + tooOld + rejected` always equals the rows in the file, and `capDropped` is
     reported. No scored row disappears silently.
   - Test owner: Task 2.
2. **Secrets leaking through side channels.**
   - Cases: the passphrase, an access token, the PKCE verifier, a B2/R2 secret, or the `?code=` / `#access_token=` left in
     the address bar, in history, in an error message, in the audit trail, in `localStorage`/IndexedDB, or echoed by the
     gateway.
   - Expected: none of them appears. The web callback URL is replaced with `history.replaceState` before any await.
   - Test owners: Tasks 4, 8 and 10.
3. **Abandoned or repeated flows.**
   - Cases: the user closes the browser during sign-in; a second sign-in while one waits; a double click on Back up now; a
     stale web callback (state older than 10 minutes, or reloaded and replayed); a restore while a scan writes ledger rows.
   - Expected: the loopback times out and frees port 48787; one operation at a time; state mismatch and stale state are
     refused with nothing changed; restored rows merge with concurrent rows through the ledger's own queue.
   - Test owners: Tasks 4, 6 and 10.
4. **Files from another version or another source.**
   - Cases: a header with `schema: 2`; an iteration count above 5,000,000 or below 600,000; `createdAt` in the future; an
     unknown cipher; extra keys in the outer JSON; a `.rslbak` or a ledger CSV picked by mistake; a file larger than 20 MB
     whose `Content-Length` is missing.
   - Expected: a clear "not a Confluence Terminal backup, or made by a newer version" or "larger than 20 MB" message,
     before key derivation where possible, and no side effect.
   - Test owners: Tasks 1, 2 and 9.
5. **A large real ledger.**
   - Cases: 300,000 rows with `rad` and `scb`/`scp` fields; a phone WebView without `CompressionStream`.
   - Expected: gzip keeps the file under 20 MB, or the backup is refused **before any upload** with the size and the
     advice to export the ledger CSV; without `CompressionStream` the file is written uncompressed, and a gzip file on such
     a device says "cannot open compressed backups"; the UI stays responsive (no long task ≥ 200 ms outside crypto).
   - Test owners: Tasks 1, 2 and 10.

| Spec item | Resolution |
|---|---|
| "Settings → Backup, collapsed" | The app has no separate Settings dialog: the native **Settings…** menu item opens About, where backups already live (guide §19). The section is a collapsed `<details data-testid="about-cloud-backup">` in About, after the existing Backup section. |
| "validates … sizes (≤ 20 MB)" vs a real ledger (about 620 B per row with `rad` and `scb`/`scp`: 20 MB ≈ 32,000 rows) | The 20 MB limit applies to the **file** (what is uploaded, downloaded and sent to the gateway). The payload is gzip-compressed inside the authenticated ciphertext, and its decompressed size is capped at 160 MB while streaming. A backup that would exceed 20 MB is refused before upload. |
| Google on the web `[builder-check call]` | No client ID exists, so a script-free code + PKCE flow without a secret cannot be verified at build. Google is **"Desktop app only"** on the web and on phones. Upload and list are unaffected. |
| pCloud "token flow" on desktop | The token arrives in the URL fragment, which a loopback server never receives. The Rust listener answers the first `/callback` with a fixed relay page that sends `location.hash` back as a query string to the same listener (`relayFragment`). |
| pCloud region host | Accepted only if it is `api.pcloud.com` or `eapi.pcloud.com` (spec). Downloads use `gettextfile` on that same host, so no file-server host is needed. Verifying `gettextfile` and Bearer auth is a deferred manual check. |
| "Sign-in in the desktop and phone apps … verified per platform at build" | Desktop: loopback. Phone: an app link needs the owner's signing fingerprint and Team ID, so it is **off unless configured** (Task 7). Until then OneDrive and pCloud show **"Web and desktop only"** on phones. B2 and R2 are "Desktop app only" there. |
| "settings" | App preferences and the scoring profile. Paper risk settings, the account and positions are excluded: restoring them could loosen an active drawdown lock (spec Success 1). Trials go with pre-registrations, because without them a restored device would under-count the deflated Sharpe's trials. |
| OneDrive refresh token (24 h) | Not used. Tokens are held for the session only (no `offline_access`), so every session signs in once. |
| §6 CORS and terms checks for the new hosts | Deferred manual checks, listed in `docs/backup-provider-setup.md` and marked deferred in ADR-0019 and the ADR-0003 amendment. A host that fails is removed and the guide says so (§6). |

### Task 1: Encrypted envelope (pure)

**Files:**
- Create: `apps/confluence/web/src/lib/backup-crypto.ts`
- Test: `apps/confluence/web/src/lib/backup-crypto.test.mjs` (script `test:backup-crypto`, added to `test`)

**Interfaces:**
- Produces:
  - Constants: `BACKUP_FORMAT = "rsl-confluence-backup"`, `BACKUP_MAX_FILE_BYTES = 20 * 1024 * 1024`,
    `BACKUP_MAX_PLAIN_BYTES = 160 * 1024 * 1024`, `PBKDF2_ITERATIONS = 600_000`, `PBKDF2_MAX_ITERATIONS = 5_000_000`,
    `MIN_PASSPHRASE_CHARS = 12`, `HEADER_MAX_BYTES = 1024`, `BACKUP_FILE_RE = /^confluence-backup-\d{8}T\d{6}Z\.json$/`.
  - `type BackupErrorCode = "too-large-backup" | "too-large-file" | "format" | "schema" | "decrypt" | "passphrase" | "unsupported" | "not-set-up" | "unavailable" | "sign-in" | "state" | "session" | "network" | "http" | "download-host" | "port-busy" | "timeout" | "cancelled" | "gateway" | "needs-gateway"`. This is the one error vocabulary for every later task.
  - `class BackupError extends Error { code: BackupErrorCode; detail: Record<string, string | number> }`. The message
    equals `code`, and `detail` carries only sizes, statuses, provider ids or origins: never a URL path, query, token, key
    or passphrase.
  - `interface EnvelopeHeader { schema: 1; cipher: "AES-256-GCM"; kdf: "PBKDF2-SHA-256"; iter: number; salt: string; zip: "gzip" | "none"; createdAt: number; app: string }`.
  - `utf8Bytes(s: string): number`.
  - `backupFileName(createdAt: number): string` → `confluence-backup-YYYYMMDDTHHMMSSZ.json` (UTC).
  - `sealBackup(plain: string, passphrase: string, opts: { createdAt: number; app: string; zip?: "gzip" | "none" }): Promise<string>`.
    - `zip` defaults to `"gzip"` when `globalThis.CompressionStream` exists, else `"none"`.
    - A passphrase shorter than 12 characters (after NFC) throws `passphrase`.
    - A result larger than 20 MB throws `too-large-backup` with `detail.size` (bytes).
  - `openBackup(fileText: string, passphrase: string, now = Date.now()): Promise<{ header: EnvelopeHeader; plain: string }>`.
  - `readBackupHeader(fileText: string, now = Date.now()): EnvelopeHeader`: every structural check, no passphrase.
- File format (not determined by the tests, so pinned here):
  - **Outer text:** `{"format":"rsl-confluence-backup","v":1,"h":"<b64url header bytes>","iv":"<b64url 12 B>","ct":"<b64url ciphertext‖tag>"}`.
    Exactly these keys. Base64url without padding, strict alphabet.
  - **Header bytes:** `JSON.stringify` of `EnvelopeHeader` in the key order above, UTF-8 encoded. These exact bytes are the
    GCM `additionalData`.
  - **Key:** `PBKDF2(SHA-256, utf8(passphrase.normalize("NFC")), salt, iter)` → AES-GCM 256, non-extractable,
    `["encrypt", "decrypt"]`.
  - **Plain:** UTF-8 of the payload text, gzip-compressed when `zip === "gzip"`, then encrypted.
  - **`openBackup` order:**
    1. `utf8Bytes(fileText) > 20 MB` → `too-large-file`.
    2. `JSON.parse`. Not an object, wrong `format`/`v`, or extra or missing keys → `format`.
    3. Strict base64url decode → `format`.
    4. Header > 1 KB, not JSON, or failing the field rules → `format`. The rules:
       - `schema === 1`;
       - the exact `cipher`/`kdf` strings;
       - `600_000 ≤ iter ≤ 5_000_000` (integer);
       - salt 16 bytes;
       - `zip` ∈ {gzip, none};
       - `createdAt` an integer in [Date.UTC(2026,0,1), now + 86_400_000];
       - `app` matching `^[0-9A-Za-z .()-]{1,40}$`.
    5. IV 12 bytes, ct ≥ 16 bytes → else `format`.
    6. Derive and decrypt. Any WebCrypto failure → `decrypt`.
    7. Decompress with `DecompressionStream("gzip")`, counting bytes and aborting above 160 MB → `too-large-file`. No
       `DecompressionStream` → `unsupported`. Corrupt gzip → `format`.
    8. `TextDecoder("utf-8", { fatal: true })` → `format` on failure.

- [ ] **Step 1: Write the failing tests** in `backup-crypto.test.mjs`. The fixture passphrase is `"correct horse battery staple"` and `createdAt = Date.UTC(2026, 10, 17, 10, 15, 0)`.
  - `round trip returns the same text and header`: `openBackup(await sealBackup(text, pass, {createdAt, app:"2.8.0"}), pass)` → `plain === text`, `header.iter === 600000`, `header.zip === "gzip"`, `header.createdAt === createdAt`.
  - `uncompressed round trip`: `zip: "none"` → same.
  - `a flipped byte anywhere fails`: decode `h`, `iv` and `ct`; flip one byte each (header byte 5, IV byte 0, ct byte 0, the last tag byte) and re-encode. Each → `BackupError` code `decrypt` or `format`, never a result. Also 8 seeded-random single-character changes inside `ct`: each rejects.
  - `the header is authenticated`: re-encode `h` with `iter: 700000` (still valid) → `decrypt`.
  - `a wrong passphrase fails`: `openBackup(file, "correct horse battery stapler")` → code `decrypt`.
  - `oversize file is refused before parsing`: a string of 20 MB + 1 ASCII bytes → `too-large-file` within 200 ms (no key derivation).
  - `oversize backup is refused before upload`: 40 MB of random base64 (incompressible) → `sealBackup` rejects `too-large-backup` with `detail.size > 20971520`.
  - `decompression bomb is stopped`: seal a 200 MB string of `"0"` with gzip (file well under 20 MB) → `openBackup` → `too-large-file`.
  - `structural rejects`: `"not json"`, a `.rslbak`-like `{"appId":"CONF"}`, an extra outer key, `schema: 2`, `iter: 599999`, `iter: 5000001`, `createdAt` two days ahead, `cipher: "AES-128-GCM"`, an 11-byte IV → each `format`. `readBackupHeader` gives the same codes without a passphrase.
  - `short passphrase`: 11 characters → `passphrase`. 12 characters → ok.
  - `NFC: composed and decomposed passphrases open the same file`: seal with `"café-passphrase"` (U+00E9), open with `"café-passphrase"`.
