# v2.8 Step 4b — Market radar part 2 (live liquidations, cascade alert, gateway provider keys) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish WP25. Show live liquidation volume from the Bybit and Binance public websockets, with a liquidation-cascade alert on a self-built 30-day baseline. Add optional paid provider profiles (Whale Alert, CoinGlass ETF flows) to the local gateway, and show their data in the Radar panel.

**Architecture:**
- **Pure core.** `lib/radar/liquidations.ts` parses messages, buckets them into UTC hours with connection coverage, and evaluates the cascade rule.
- **Feed.** `lib/radar/liquidation-feed.ts` owns the two sockets through an injected WebSocket constructor and a RadarPort for persistence.
- **Runners.** The existing radar runner starts and stops the feed under the same gate. The recorder reuses the same TypeScript through `engine.mjs`, with an egress-guarded WebSocket.
- **Gateway.** Provider keys live only in the gateway, in a separate provider-profile kind. Two `.mjs` modules are added: verification and data. The web app calls the gateway's data routes only while the radar is allowed.

**Tech Stack:** Next.js 15 / React (static export), TypeScript run by `node --experimental-strip-types` tests, Node 22 gateway and recorder (global `WebSocket`, `fetch`), Playwright 1.63 acceptance (`page.routeWebSocket`, `page.route`).

**Spec:** `docs/superpowers/specs/2026-11-15-v2.8-architecture-design.md` rev 12, §WP25 (lines ~377–432), plus §6 (hosts) and §3 (design unchanged at rest).

## Global Constraints

- Context, never a vote: nothing in this step reaches scoring. No radar alert blocks or places a trade, and the paper risk rules are unchanged.
- Fetch gate: radar hosts, both websockets and the gateway provider data routes are contacted only while `radarAllowed({ panelOpen, recordRadar })` holds. The default build at rest opens no socket and makes no radar request (guide §16).
- Websocket URLs, verbatim. Binance: `wss://fstream.binance.com/market/ws/!forceOrder@arr`. The legacy `/ws/` path is silent (probe of 16 Nov 2026, `docs/research/evidence/`). Bybit: `wss://stream.bybit.com/v5/public/linear`, topics `allLiquidation.BTCUSDT` and `allLiquidation.ETHUSDT`, ping `{"op":"ping"}` every 20 s.
- Binance pushes only the latest liquidation per symbol per second. It is labelled **"sampled"** wherever it is shown.
- 30-day baseline. It is built from the device's own log of complete UTC hours. A missing or incomplete hour is left out, never counted as zero. The cascade alert shows "collecting" until 720 complete hours exist for that venue.
- Cascade rule (starting value, adjustable): last-60-minute liquidations ≥ **3 ×** the median complete hour.
- Paid keys: only in the gateway, in memory, and cleared at exit and on crash. They are never in the web app's storage, the repository, a backup, a log line, an error message or a gateway response. Masked key only (`maskApiKey`).
- WP19's read-only refusal stays for exchange keys. Provider keys are a separate kind. Required test: an exchange key with write permission is still refused, and a provider key is accepted.
- Web build without a connected provider profile: the rows say "{label} — Available with a key on the desktop gateway" (existing `radar.gateway`).
- New hosts. Each needs an ADR-0003 amendment, `tools/egress-manifest.json`, and for web hosts `CSP_HOSTS` in `public-hosts.ts`, the desktop CSP in `tauri.conf.json` and R8.
  - Web: `wss://fstream.binance.com`, `wss://stream.bybit.com`.

## Review Focus

1. **Socket churn and leaks.** Open and close the panel quickly, toggle Record radar, or let a tab sleep. Expect exactly one socket per venue while allowed, none after stop, and no reconnect timer firing after stop. Test owner: Task 2.
2. **An hour with a gap counted as complete.** A 2-minute disconnect inside an hour must make that hour incomplete. It is left out of the baseline and never logged as a low hour. Test owners: Tasks 1 and 2.
3. **Key leakage through errors.** The Whale Alert key sits in the socket URL query. A failed connection, an `error` event or a thrown `TypeError` must never surface the URL or the key in a response, log or exception message. Test owners: Tasks 5 and 6.
4. **Hostile provider payloads.** Expect a huge `etf_flows`, missing `flow_usd`, non-string tickers, `from`/`to` strings containing markup, and amounts of NaN or 1e30. Every field is validated and capped, and text is rendered as text. Test owners: Tasks 6 and 8.
5. **Gateway restarted (new token) while the panel is open.** Provider calls then fail with 401. The rows show the existing gateway message (not an endless spinner, not a crash), and the rest of the radar keeps refreshing. Test owner: Task 8.

**Interfaces:**
- Produces:
  - `type LiqVenue = "bybit" | "binance"`; `interface LiqEvent { venue: LiqVenue; symbol: "BTCUSDT" | "ETHUSDT"; side: "long" | "short"; usd: number; t: number }` (`side` = the side that was liquidated).
  - `parseBybitLiq(msg: unknown, now: number): LiqEvent[]`. `S === "Buy"` → `long`, `"Sell"` → `short`. `usd = v × p`. `t = T`.
  - `parseBinanceLiq(msg: unknown, now: number): LiqEvent[]` (0 or 1 event). `o.S === "SELL"` → `long`, `"BUY"` → `short`. `usd = z × ap` when both > 0, else `q × p`. `t = o.T`. Only `BTCUSDT`/`ETHUSDT`.
  - Both drop: non-finite values or `usd ≤ 0` or `usd > 1e10`; `t > now + 60_000` or `t < now − 2 h`; other symbols. They never throw.
  - `const LIQ_HOUR_MS = 3_600_000`, `LIQ_BASELINE_HOURS = 720`, `LIQ_MAX_GAP_MS = 10_000`, `LIQ_KEEP_HOURS = 1000`, `LIQ_KEEP_MS = 180 × 86_400_000`.
  - `interface LiqHour { h: number; long: number; short: number }` (`h` = UTC hour start, ms).
  - `class HourBook`:
    - `constructor(venue: LiqVenue, hours?: LiqHour[])`.
    - `connected(t)` / `disconnected(t)` coverage marks.
    - `add(e: LiqEvent)`.
    - `roll(now): LiqHour[]` returns hours that just closed complete. An hour is complete when the venue was connected from `h` to `h + 1 h` with every disconnection inside it lasting ≤ `LIQ_MAX_GAP_MS`.
    - `last60(now): { long: number; short: number; coveredMs: number; complete: boolean }`. `coveredMs` = connected time inside `[now − 1 h, now]`. `complete` = same gap rule over that window.
    - `hours(): LiqHour[]`, oldest first, ≤ `LIQ_KEEP_HOURS`, none older than `LIQ_KEEP_MS`.
  - `normalizeLiqDoc(raw: unknown, now: number): Record<LiqVenue, LiqHour[]>`. Re-validates every hour: `h` is a whole multiple of `LIQ_HOUR_MS`; `long`/`short` are finite and in [0, 1e11]; deduplicated by `h`; sorted; trimmed.
  - `liquidationCascade(venue: LiqVenue, hours: LiqHour[], last60: {...}, th: RadarThresholds, now: number): { status: "collecting"; have: number } | { status: "ready"; medianUsd: number; alert: RadarAlert | null }`.
    - Baseline = median of `long + short` over the newest 720 complete hours.
    - `alert` when `last60.complete` and `last60.long + last60.short ≥ th.liqMult × median` and `median > 0`.
    - Code `LIQ_CASCADE_BYBIT` / `LIQ_CASCADE_BINANCE`, `kind: "liquidation"`.
    - Trigger `radar.alert.liq` with vars `{ venue, usd, mult, median, longPct }`.
    - `since = now − LIQ_HOUR_MS`.
    - `sourceUrl` = the venue's docs page via the existing `pageOf` helper (export it, or reuse `PROVIDERS`).
- `alerts.ts`:
  - `RadarThresholds` gains `liqMult` (default 3, range 1.5–20) and `whaleMinUsd` (default 10_000_000, range 1_000_000–10_000_000_000, whole numbers).
  - `RadarAlert.kind` gains `"liquidation" | "whale"`.
  - `sanitizeThresholds` covers both. Old stored objects without the keys get the defaults.

  - `interface LiqVenueView { connected: boolean; since: number | null; long: number; short: number; coveredMs: number; complete: boolean; sampled: boolean; cascade: ReturnType<typeof liquidationCascade> }`.

- Feed behaviour:
  - `start()` is idempotent and opens one socket per venue.
  - Bybit: sends `{"op":"subscribe","args":["allLiquidation.BTCUSDT","allLiquidation.ETHUSDT"]}` on open. It counts as connected only after a reply with `success: true` for that subscribe. It pings every 20 s.
  - Binance: connected on open.
  - On close or error: `disconnected(t)`, then a reconnect after backoff 2 s, 4 s … capped at 60 s. Backoff resets after 5 min connected.
  - `stop()` closes both sockets, clears every timer, and stops any pending reconnect. Nothing fires after `stop()`.
  - At each message or every 60 s, `roll(now)`. Newly complete hours are saved through the store's `serialised` queue into `radar-liq` as `{ v: 1, hours: { bybit: LiqHour[], binance: LiqHour[] } }` (normalised on load). A read failure starts empty and never throws.
- Runner (`snapshot.ts`):
  - `RadarRunnerDeps.liquidations?: LiquidationFeed`. `start()` / `stop()` of the runner call the feed's `start()` / `stop()` (the gate is the same `permitted()`).
  - `RadarSnapshot.liquidations: LiqView | null`. `unavailable` gains `liq:bybit` / `liq:binance` while that venue is not connected.
  - `composeAlerts` appends each venue's cascade alert. `rethreshold()` recomputes them from `feed.view(now, th)`.
  - `toRadarContext.al` carries `LIQ_CASCADE_*` codes like the others.
- Hosts:

    - `EtfLive = { asOf: number; btc: EtfDay[]; eth: EtfDay[] }`, where `EtfDay = { date: "YYYY-MM-DD"; totalUsd: number; flows: { ticker: string; flowUsd: number }[] }`.

    - The subscribe uses `min_value_usd = clamp(minUsd, 1e6, 1e10)`. A later poll with a different clamped value reconnects with it.
    - Reconnect backoff 5 s … 5 min.
    - Buffer: last 24 h, ≤ 200 newest.
    - `WhaleAlert = { t: number; chain: string; kind: string; from: string; to: string; symbol: string; amount: number; valueUsd: number; hash: string }`. It takes the largest `amounts[]` entry.
    - Strings: `chain`/`kind`/`symbol` match `/^[A-Za-z0-9 _.-]{1,32}$/`. `from`/`to` keep their text but are cut to 80 chars and stripped of control characters. `hash` matches `/^[A-Za-z0-9]{1,100}$/`, else `""`.
    - `valueUsd` and `amount` are finite and in (0, 1e12]. An invalid alert is dropped.
  - Routes:
    - `GET /providers/etf-flows` → `EtfLive`. It uses the newest CoinGlass profile; none → 409 `{ error: "No ETF-flow provider key is connected." }`. The result is cached 1 h in memory.
    - `GET /providers/whale-alerts?min=<usd>` → `{ connected, alerts }`. It uses the newest Whale Alert profile; none → 409.
    - Deleting the profile closes its stream. `clearSecrets()` closes all streams.
