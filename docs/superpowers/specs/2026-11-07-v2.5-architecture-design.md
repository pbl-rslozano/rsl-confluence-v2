## 2. Work packages

Delivered as one release, **v2.5.0**, on a branch merged to `main` through a pull request (§8).

### WP1 — Restore the mobile list (owner choice: Expand button)
- Re-apply build 20261101 on top of v2.4, merging by hand where v2.4 changed the same code (new header controls,
  watchlists, alert inbox). Pieces: `listExpanded` state (per-device, guarded storage), list toolbar with count /
  timeframe / source / last update / refresh in expanded mode, header and informational notes hidden when
  expanded (alerts stay), `.ct-app-shell { position: fixed; inset: 0 }` + `html.ct-shell` scroll lock, compact
  footer, 16 px text inputs on coarse pointers, `list.expand|collapse|expandHint` in 18 catalogs.
- v2.4 added header rows (watchlists, alert inbox, scoring profile, saved scans), so the header is taller on
  phones than in 2.3. Expanded mode is therefore the main phone view; the plan also collapses the secondary
  header rows behind one "More controls" disclosure below 640 px.
- Close `hotfix/v3.43-mobile-ui-hotfix1` without merging (superseded); keep its footer-measuring idea only if
  M-20 fails on a device.
- Acceptance: **M-20** restored (list ≥ 2× taller expanded; footer bottom = viewport; document scroll 0;
  remembered), plus **M-21** at 360×740 and in RTL.

### WP2 — One app icon on every platform
- Single source: `apps/confluence/desktop/src-tauri/icons/source-512.png` (already the rsL tile). Generated sets
  already exist for Android (`icons/android/mipmap-*`, adaptive `mipmap-anydpi-v26`) and iOS (`icons/ios/AppIcon-*`).
- `tools/apply-native-config.mjs` gains `icons`: copy Android mipmaps into `android/app/src/main/res/` and
  write iOS `AppIcon.appiconset` (PNGs + `Contents.json`) in `ios/App/App/Assets.xcassets/`. Same for the
  splash background colour (`#0B1B33`).
- PWA/Windows/macOS unchanged (already rsL). One script regenerates every size from the source
  (`tauri icon` is already the generator) so the platforms cannot drift.
- New release check **R13 — icon identity**: after the native builds, extract the launcher icons from the APK
  (`res/` PNGs) and IPA (`AppIcon60x60@2x.png`, CgBI-decoded) and compare against the generated set (exact hash
  for Android; perceptual match ≥ 0.98 for iOS, which recompresses). Fails the release on mismatch.
  REA `inspect-artifact` evidence is kept with each release as the audit record.

### WP3 — Language menu readable everywhere
- Ship **subset fonts for the menu labels only**: Noto Sans Devanagari, Noto Sans Bengali, Noto Nastaliq Urdu,
  Noto Naskh Arabic, Noto Sans SC/JP/KR — each subset to the exact glyphs of the native names in `LANGUAGES`
  (≈ 1–8 KB per script, OFL 1.1, vendored, no CDN). Built by `tools/build-menu-fonts.mjs` (fontTools
  `pyftsubset` in CI) from pinned upstream files with SHA-256 checks; output committed under `public/fonts/menu/`.
- Language menu rows use these as the first family for their `lang`; full UI text keeps the system stacks
  (Nirmala UI / Noto / YaHei …) — loading full CJK fonts (5–15 MB) is not justified.
- Contrast: English names to the 4.5:1 token (`--text-2`); row height 44 px (48 px on touch); visible focus;
  the menu becomes a bottom sheet below 640 px so it never clips off-screen; flags stay inline SVG.
- Acceptance: **ID-8.12** screenshots of the open menu on Windows, macOS and Linux GitHub runners; a glyph check
  fails if any native name renders with `.notdef` (compare rendered width vs. fallback box); axe contrast pass.

### WP4 — Certify the 16 languages (owner choice: automated checks + reviewer sign-off)
Two layers; only the second can say "certified".
1. **Automated (every push, GitHub Actions `i18n` job):** existing `test:i18n` (parity, ICU, CLDR plurals,
   brand tokens) plus: glyph coverage per catalog against the shipped/system stacks; text fit — Playwright
   renders header, list toolbar, dialogs and footer at 390 px and 1366 px in each language and fails on
   clipped or overflowing labels; safety strings (`paper.banner`, `status.disclaimer`) must contain the
   approved meaning markers listed in `docs/translation-review.md`. Passing sets `@status: MACHINE-CHECKED`.
2. **Human certification (GitHub pull request):** a "Certify <language>" PR template with the reviewer
   checklist from `translation-review.md`. The PR changes `@status` to `CERTIFIED` and fills `@reviewer`,
   `@certifiedAt`, `@certifiedCommit`. A CI rule rejects `CERTIFIED` unless the PR has an approving review and
   the reviewer field is set; any later edit to that catalog drops it back to `MACHINE-CHECKED` automatically.
- About and the language menu show the real state per language: Certified (name, date) / Machine-checked /
  Draft. English and Arabic remain APPROVED.
- Note: Claude and other LLM checks may assist reviewers but never set `CERTIFIED`.

### WP5 — Theme switch to industry standard
- **Tokens, not overrides.** Semantic CSS variables from the Core Kit DTCG token sets — `--surface-0/1/2/3`,
  `--text-1/2/3`, `--border-1/2`, `--accent`, `--bull/--bear/--neutral`, `--bar` — defined for
  `:root[data-theme="dark"]` and `:root[data-theme="light"]`; Tailwind v4 `@theme` maps utilities
  (`bg-surface-1`, `text-2` …) to them. Components move from hard-coded `zinc-*` to semantic utilities, header
  and dialogs first. The `[class*=…] !important` block is deleted.
- **Header in light theme** uses the light bar tokens (brand gradient on a light surface), so no control ever
  sits dark-on-dark. (Alternative kept dark by token — decided in review, default: light.)
- **Three choices:** System (default, follows `prefers-color-scheme` live), Light, Dark — a segmented control.
- **No mixed frames:** theme set on `<html data-theme>` before first paint (existing inline script, now also
  handling System); during a switch, a `theme-switching` class disables transitions for one frame; optional
  cross-fade via View Transitions where supported and motion is allowed.
- **Platform chrome follows:** `<meta name="theme-color">` updated per theme (light `#F5F7FA`, dark `#0B1B33`);
  `color-scheme` set; Android/iOS status bar via Capacitor StatusBar; Tauri window theme set to match.
- **Charts and canvases** read tokens at draw time and redraw on change.
- Acceptance: **T-1** axe contrast in both themes at 390/1366; **T-2** no element with a dark background
  ≥ 2,000 px² in light theme (and vice versa); **T-3** first frame after switching has one theme only;
  **T-4** theme-color and status bar match.

### WP6 — Update channel (from 7 Nov proposal "A"; pending owner approval)
- GitHub Actions remains the only builder. After the gate passes on `main`, a `publish` job deploys the PWA to
  Netlify site **effervescent-bubblegum-1e5c03** (secrets `NETLIFY_AUTH_TOKEN`, `NETLIFY_SITE_ID`) together with
  `/updates/latest.json` (version, build, notes, APK name, size, SHA-256) and the signed APK under `/updates/`.
- Web/PWA: service worker announces a waiting version → "A new version is ready — Reload".
- Android: checks `latest.json` at launch and every 6 h (switch in Settings, default on); "Update available"
  opens the APK in the system installer; same signing key keeps data.
- iPhone and desktop: notice only (Sideloadly / next installer; desktop updater still deferred per ADR-0005).
- ADR-0003 amendment + R8: add `https://effervescent-bubblegum-1e5c03.netlify.app` (read-only GET of
  `latest.json`). The app never contacts GitHub. To verify during build: Netlify per-file size limit for the
  ≈ 20 MB APK (fallback: notice links to the GitHub Actions artifact page).

## 3. Release integrity (prevents F1/F2 recurring)

- **Branch protection on `main`:** changes only via pull request; required checks = release gate + i18n +
  R13; no force pushes.
- **AGENTS.md and CLAUDE.md at the repo root** (read automatically by Codex and Claude Code): "Start from the
  current `main`, never from a zip; never upload a snapshot over `main`; merge with Git (three-way); keep the
  acceptance suite — removing a check needs an ADR."
- **Feature guard:** acceptance IDs are listed in `docs/acceptance.md`; a release check (**R14**) fails if an ID
  present on `main` disappears from `tools/e2e/acceptance.cjs` without an ADR reference.

## 4. Sequencing and checks

1. Branch `release/v2.5` from `main` @ 35d1fde. 2. WP1 + R14 + AGENTS/CLAUDE (restores and guards). 3. WP5 (theme
tokens; touches the same files as WP1, so second). 4. WP3. 5. WP2 + R13. 6. WP4 automated layer; certification
PR template. 7. WP6 (only after approval). 8. Full gate: unit tests, release checks, acceptance (v2.4's 105 +
new IDs), REA inventory of APK/IPA, axe both themes. 9. PR → review → merge → platform builds.

  verified only on GitHub runner images, not every device.
