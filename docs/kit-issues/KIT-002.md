# KIT-002 — Remove all organisation details from the kit (v1.1 2026)

**Kit:** rsL Core Kit v1.0 → **v1.1 2026** · **Decided:** 14 Nov 2026 by rsLozano (owner) · **Severity:** high (public build)

## Problem
The licence audit of v2.7.0 (14 Nov 2026) found that `core/rsl-brand.js` held an organisation's name, a confidentiality line,
a department and department-head credit, a list of site codes and an organisation's default customer and colours. The
`BRAND` object is a frozen module-level literal, so any import kept all of it inside the public web, desktop and mobile
bundles (in an obfuscated chunk), although the app never displayed it. The kit README carried the same lines, and the
kit tests used organisation names as fixtures.

## Decision
The owner decided to remove every organisation detail from this repository and its builds.

## Change (v1.1 2026)
- `core/rsl-brand.js`: `credit` is "Created by rsLozano"; `confidential` and `factories` removed; `footerLines` no longer
  adds a confidentiality line; `defaultCustomer` is the personal workspace (`rsLozano — Personal workspace` / `Personal` /
  `PERS`, rsL blue and violet); `RSL_APPS` lists this app only.
- `core/rsl-identity.js`: default site and operator role are empty.
- `tokens/rsl.tokens.json` → `rsl-tokens.css`: customer colours are rsL blue `#0755F5` and violet `#7524F4`.
- `README.md`: personal edition note and credit; version v1.1 2026.
- `tests/core.test.mjs`: neutral fixtures (Northwind, Example Trading Co., S1/S2); asserts the personal credit and that
  `BRAND` has no confidentiality line or site list.
- `KIT-MANIFEST.sha256` regenerated (release check R4).

## Guard
Release check **R22** (`tools/checks/no-org-ids.mjs`, tests in `tools/no-org-ids.test.mjs`) scans the source tree and the
built web output, decoding `\xNN` / `\uNNNN` escapes, for the guarded words. The words are stored only as salted SHA-256
prefixes, so the check names nobody. Acceptance check ID-2.4 uses the same word list on the About dialog.

## Not covered
Git history before this change and builds already published (v2.7.0 and earlier) still contain the old strings. The
repository is private; the next release (v2.8) replaces the public web build and the app downloads.
